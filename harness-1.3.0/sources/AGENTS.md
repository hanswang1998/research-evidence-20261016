## 共用边界

- 当前用户指令与有效授权优先于旧交接的角色、模型、期限或持续要求；文档修改不构成研究恢复、支出、扩源、定时、上线或实盘授权。各线暂停、预算和执行权互不继承。
- 主策略与 Rust 分别使用 `current.execution_by_line.main_strategy`／`rust_replay`。区分用户暂停研究、提交控制暂停、缺机器可读收据：后两者限制新提交，已有授权内的分析和独立候选准备可继续。已有明确授权准确登记，不编造、扩权或重复索要同一许可。
- 状态只读一次并报告观察时刻，不等待版本静止、不追查并发写入者。共享写入用短锁和版本校验，冲突只重读受影响字段；独立目录的已授权工作继续。旧“rev 在动就禁止任何写入”规则失效。
- 共享容量只在具体提交时核对；阻塞说明写清动作、所属线、资源／文件、证据、解除条件及仍可继续的工作。真实依赖写入该实验合同，不把其他线暂停或等待工程验收扩大为本线停工。未知任务按原身份核实，不重复提交。
- 在途冻结件按原版完成；新规则只在下一合法未冻结边界接入。保留失败、未知、身份、时序、现金和独立验证边界，摘要或消息不替代执行证据。
- 输入、实现、判据未变且无新疑点时复用有效核验；有差异再补受影响范围，必要回归不省略。大表、日志与历史先限路径、日期和字段，不默认遍读研究库。
- 实质结果按[研判与选题核心](docs/harness/研判与选题.md)在原记录串起“原判断→关键证据→判断更新→下一动作”。先分清实验问题、工具缺陷和 Harness 方法缺口；已授权持续研究内自主纠偏与接续，阶段汇报不代替下一步，不重复索要已有许可。规则修订只在下一合法未冻结边界使用。

## 按动作读取的权威正文

| 动作 | 正文及职责 |
| --- | --- |
| 核对目标／判定结果 | [目标与评价核心](docs/harness/目标与评价.md)；读取器按评价阶段加载[原验收细则](docs/研究验收标准.md)，状态从本线原件读取 |
| 准备、选题、反思 | [研判与选题核心](docs/harness/研判与选题.md)；深入诊断、反思或方法试验时按动作读取[原能力细则](docs/研究能力改进规范.md)对应章节 |
| 批次与操作 | [持续迭代](docs/总目标与持续迭代.md)：状态、提交、冻结及反思边界；[调度提示词](docs/研究调度提示词.md)对应动作段落规定选择、核验和纠偏 |
| 实际调度／分支试点 | [运行手册](docs/研究调度运行手册.md)规定 next／observe／cycle 接口；[分支试点](docs/分支研究试点.md)规定假设池接入。结构／旧 ML 按既有分支，专题按本线已实现入口；不以文档宣称已接入或提效 |
| 计算与明细处理 | 主策略 ML 按[ML 计算指引](docs/主策略机器学习计算指引.md)，高涨幅按[高涨幅计算指引](docs/高涨幅计算指引.md)；仅适配当前需要的链条 |
| 新增或修改写入链条 | [研究产物治理](docs/研究产物治理.md)：复用、格式、摘要引用、文件量／字节及恢复验证；不授权批量删除或新增计算 |

已读且未变的正文按需复用，不按轮全量加载。状态查询和普通维护不加载研究循环；本表不新增台账、审批或自动化。

共用 Harness 的版本按[版本管理](docs/harness/版本管理.md)记录；受管入口、规则或程序的一次有意义改动完成必要核验后，核对差异并登记新版本。登记与各线实际绑定／采用分开；普通查询、未改动的维护和每轮研究不升版本，在途冻结件沿原版。

这两类动作在下一未冻结边界通过 `python -X utf8 -B engine/research_guidance.py read --phase select --line <本线标识> --run-dir <原计划或批次目录> --actor <执行者>` 读取；目标用 `goal`，评价用 `evaluate --stage information|engineering|economic`，反思用 `reflect`，独立确认用 `confirm`，方法试验用 `method`。本线入口旧的整页导读在此范围改为核心加按需章节；已冻结引用仍按原件。返回的指引快照在原 PLAN／SPEC 绑定并复用；本轮依据未变不重复读取。实际依赖某规则时在原产出相应段引用返回的 guidance 标记，再用 `record-use` 记录引用，不能为了埋点堆标记。仅记录该入口与任务组装可观察的内容，绕过入口或未记录都保持未知，读取不等于执行或提效；[用法与边界](docs/harness/读取与使用观测.md)。
