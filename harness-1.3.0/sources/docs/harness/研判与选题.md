# 研判与选题 · 核心

规则 `judgment-20261016-v2`；读取器 `guidance-20261016-v1`。下一合法未冻结边界使用；复用原 PLAN／SPEC、反思与核验。

1. **为什么值得做？** 写收益机制、条件、修改层和经济瓶颈；引用证据、反例、未知及竞争解释，说明与旧失败的实质差别。故事、相关和特征重要性不作因果证明。
2. **问题卡在哪？** 沿机会→信号→排序／仓位→成交→退出→费后账户诊断；兼看盈利、亏损和遗漏机会，保留母体及支持量，区分信号、标签、动作未触达、资金路径、费用和工程故障。
3. **最小怎样分清？** 固定父本、对照、预期动作、来源与决定前可知时点、证伪和不同结果的去向。冻结前核对样本支持及代理是否覆盖真实筛选／执行；成本含生成、实现、执行、核验、沟通与产物，未知不补零。
4. **为什么先做它？** 先核来源、时点、可执行性和关键正确性，再比影响、证据、区分能力、成本及依赖；不凑机制、不编概率，不改原选择器、接口、冻结法或权限。
5. **结果改变了什么？** 原记录串起“原判断→关键证据→判断更新→下一动作”，下一 PLAN／SPEC 引用结论，写修改对象、对照与证伪。继续须说明剩余未知；保留失败范围及重入新证据，不改名救回、不以单次失败封死机制族。

**证据分流：** 代理不可比／支持不足，先限定解释、补可比性；胜随机却输父本，查费用、名额、现金与持有窗口；动作未触达，查实现和约束；收益靠加仓／少数交易，定向归因；可比账户否定固定表达，关闭该表达。

**改版时机：** 实验错就改下一实验；工具错就定向修复；提示词、生成、上下文或协作造成明确误判、重复无信息工作或错误停工，才提方法候选，不等用户纠偏。一次亏损不够自证。候选另存，保留成功行为、验证与回退，下一未冻结边界绑定；不放宽判据或扩权。

**自主接续：** 持续授权内直接选下一合法动作，汇报、单个失败、池暂少或方法试点待核不自动停工；有据补池，不伪造 ready。用户暂停、合同停止条件、预算与真实依赖仍有效，不重复索要已有许可。
