# Harness 版本管理

共用 Harness 从 **1.0.0** 开始登记。这个编号表示首次保存的现状基线，不补造历史版本，也不表示所有研究线已经采用或方法已验收。

## 管哪些内容

范围以 [文件清单](../../engine/harness_version_scope.json) 为准：项目入口、共用研究规则、调度／Harness／指引／控制程序及默认配置、版本管理本身。各线的私有执行器、策略、STATE、账户数据、看板展示、外部 Skill 继续按原来源管理；不把它们笼统装进总版本。更改清单本身也构成版本差异。

版本分三层：

| 层级 | 身份与用途 |
| --- | --- |
| 共用 Harness | `1.0.0`、父版本、变更说明、全清单内容 SHA、记录时间；用于查看、比较、恢复 |
| 组件／格式 | 原 `research_harness.v1`、`guidance-20261016-v1` 等保持各自含义；schema 号不是整套 Harness 版本 |
| 研究实际输入 | 原 PLAN／BATCH／CONTRACT／TASK 中的路径、SHA、冻结程序及指引快照；这是实际绑定依据 |

同一组件可以被多个总版本复用。只匹配一个调度器 SHA 只能说该组件一致，不能说整套版本已采用。无绑定证据标“未核实”；旧冻结版本继续执行是正常状态，不自动废弃。

## 什么时候升版本

在一次有意义的共用改动完成、必要核验通过后登记，不按每次文件保存或每轮研究递增。

- **主版本** `2.0.0`：目标、评价口径、权限边界、关键流程或输入合同发生不兼容变化。
- **次版本** `1.1.0`：兼容地增加能力、规则入口或观测方式，既有冻结合同仍能按原版完成。
- **修订版** `1.0.1`：文案、链接、明确不改变研究行为的实现修正。

行为修复通常按次版本；不能只因为改动行数少就记修订版。版本工具检查递增与内容差异，改动语义由维护者如实说明。

## 怎样登记和查看

```powershell
python -X utf8 -B engine/harness_versions.py status
# 先审阅 changes；把 working.content_sha256 填入 --expect。
python -X utf8 -B engine/harness_versions.py record --version 1.0.1 --type patch --summary '具体改了什么、为什么、如何验证' --expect <观察到的内容SHA>
python -X utf8 -B engine/harness_versions.py verify --version 1.0.0
python -X utf8 -B engine/harness_versions.py diff --from 1.0.0 --to current
python -X utf8 -B engine/harness_versions.py diff --from 1.0.0 --to current --path docs/harness/目标与评价.md
```

每版只新增 `docs/harness/versions/v<版本>.zip` 一份文件，内部 `MANIFEST.json` 保存父版、变更、逐文件 SHA、原字节大小与范围，`sources/` 保存当时原字节。压缩存储仅限这份有界小清单，不复制研究库。版本拒绝覆盖、拒绝无变化升版；准备在锁外，发布前用短锁重核父版和文件内容。中断留下的锁／临时文件需核实归属后处理，不自动删除。

看板“项目 Harness → 版本记录”读取同一归档，展示版本说明、文件差异、未登记变化和原冻结调度器的组件匹配。归档损坏或观察失败明示未知。哈希是内容身份与损坏检测，不是防篡改认证，也不证明研究行为或效果。

## 登记、绑定、采用分别记录

登记不修改任何研究线的当前状态。下一合法未冻结边界确实选用某版本时，在**原** PLAN／SPEC 的依据段引用该版本包绝对路径及 SHA，同时沿用原入口对实际源码、规则、TASK 的精确冻结。只使用部分组件时明确列出部分，不能填“整套采用”；未适配消费者也不能因为写了版本号就认定接通。不强行扩充已有严格 schema，不回写旧冻结 PLAN。

候选 → 独立复核 → 配对比较 → 有界试点 → 反馈，继续使用 [原 Harness 合同](../Harness反思与改进.md) 的 PROPOSAL／REVIEW／GENERATION／BATCH／PILOT_REVIEW，不另建第二套采纳状态。研发总版本和单组件方法候选也不是同一编号；候选资格、实际试点和方法有效性分别按原证据判定。登记工具不自动批准候选、切换研究线、运行回测或改变权限。

## 回退与验收

```powershell
python -X utf8 -B engine/harness_versions.py restore --version 1.0.0 --out tmp/harness_v1_review
```

先校验归档，再恢复到一个不存在的新目录，逐字节核对；不原地覆盖工作区或在途冻结件。核对差异后，共用文件需要回退时形成一个注明回退原因的新版本；研究批次继续沿原合同的 `fallback_harness` 和下一未冻结边界处理。

写入器的核验见 `tests/test_harness_versions.py`：覆盖旧版不变、并发冲突、缺失／损坏、范围与路径边界、版本递增、变更比较及精确恢复。登记时输出版本包路径、SHA 和实际字节数，归档清单给出源文件数与逻辑字节；没有另建研究台账、计时器或自动升级任务。
