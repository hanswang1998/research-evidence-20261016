2026-10-17，基于共用 Harness 1.1.0 选择性吸收 Claude `harness-v2`（提交 `27b676b85c70cf552ec2a0c920c960093edfe8bf`）的摘要、计时、分类和对照思路。实现随共用版本封存；这页不登记任何研究线已经采用，也不改变各线目标、预算、权限、在途冻结件或独立确认要求。

工具接口已实现；各线实际使用、闭环运行和真实提效需要原执行回执。没有方法缺口时继续本线已授权研究，不为了使用工具增加仪式性步骤。

写入前在原计划预估：摘要 2 个文件；run 计时 2 个，start 1 个、stop 新增结束与关闭标记 2 个；成本收据 1 个；分段结果及冻结评分器 2 个；线上对照 1 个。命令完成输出的 artifact_usage 给出新增文件数、逻辑字节和零覆盖重写量，填回原任务回执，不另建逐文件台账。大输入仍引用原件；中断留下的起始件／部分输出保持可见，不能算完成。

## 1. 有界状态摘要

`engine/research_line_digest.py` 是可选读取器。配置中的路径相对项目根目录；字段用 JSON Pointer。关闭项完整容纳不下时明确报错，不能悄悄省掉历史否定项。配置只匹配哪些字段／记录，摘要就只声称覆盖哪些；它不证明整条线已被审阅。反思文件按文件名自然排序取最近若干项，不将 mtime 当实验时间。

```json
{
  "schema": "research_line_digest.v1",
  "line": "本线标识",
  "state": "本线真实路径/STATE.json",
  "fields": [{"pointer": "/status", "chars": 800}, {"pointer": "/next_action", "chars": 1200}],
  "closed": {"key_pattern": "^closed_", "fields": ["id", "status"], "chars_per_row": 240},
  "max_chars": 20000
}
```

字段、关闭项匹配式按本线原件适配，不把此示例当所有线的状态格式。

```text
python -X utf8 -B engine/research_line_digest.py --config <已核配置.json> --root . --out <本批目录/STATE_DIGEST.md>
```

输出摘要及 `.receipt.json`，记录原件完整 SHA256、配置与输出哈希。路径只写一次；下次观察使用新路径。原件若变化，旧摘要仍只代表它记录的那一刻，不自动晋升为当前状态。

## 2. 当场计时与原成本收据

`engine/research_timing.py` 只包装调用者本来有权执行的动作，不提供执行授权。

```text
python -X utf8 -B engine/research_timing.py run --event-id <全轮唯一事件> --phase execution --resource <实际资源标识> --out <timer.json> -- <原执行命令及参数>
python -X utf8 -B engine/research_timing.py start --event-id <唯一事件> --phase generation --resource <agent标识> --out <start.json>
python -X utf8 -B engine/research_timing.py stop --start <start.json> --out <finished.json>
python -X utf8 -B engine/research_timing.py receipt --cost-contract <原成本合同.json> --subject <原TASK或D回执.json> --kind harness_attempt --timer <finished.json> --out <receipt.json>
```

五阶段仍为 generation、execution、verification、maintenance、communication。未计时阶段默认 null；只有确认完全没有该活动时才能加 `--none <阶段>` 写为 []。`--kind` 按原接口使用 decision、evolution、harness_attempt 或 harness_evolution。资源标识应指向实际同一活动资源；重叠计时、重复事件、时长与起止不一致均拒绝。阶段等待不能记成 Agent 或计算资源活动时间。

`run` 在启动命令前写独占起始收据，失败退出仍记耗时；再次使用该输出身份不会重复执行。起始收据存在而结束收据缺失时按原任务身份核实，不能自动重跑。收据仍由原 `read_cost_receipt`、配对去重和预算规则核验；手写数字不能因用了工具就免审。

## 3. 结果分类

`engine/research_outcomes.py classify <原status> --kind <原record_kind>` 和 `ledger --csv <有界CSV>` 只做描述。精确映射 valid_improvement、valid_negative、verified_information、implementation_error、evidence_gap 等既有标准状态；非标准历史文案保留为 unclassified，不做子串猜测。不回写原状态，不把 completed、pass、closed 等词当经济成功。即使标签为 improvement，也仍需回到账户原件核验。

## 4. 开发期分段检查

文件保留 `research_walkforward.py` 名称便于追溯，但本版行为明确为**开发期分段诊断**，没有滚动重训，也不增加独立样本外证据。不读取本线目标来替换阈值；只有显式提供输入才运行，不自动接到 `observe` 的经济晋级条件。

所有引用为绝对 `path` 与文件 `sha256`。四种输入结构：

- `research_calendar.v1`：`source` 是原交易日历来源引用；`anchor_date` 是期初权益日期；`dates` 是其后完整、有序、无重复的共同交易日。
- `research_segment_contract.v1`：`account_contract` 引用原账户参数／判据；`calendar` 引用上项；`annual_days` 是事先约定年化基准；`windows` 为完整分割日历的 `{id,start,end}` 列表；`criteria` 明确给出 `min_wins`、`max_drawdown`、`min_mean_annual_delta`。不提供通用默认值；不改原目标。
- `research_equity_run.v1`：`run_id`、`account_contract`、`implementation`（实现引用）、`grade_evidence`（原账户评价证据引用）、`equity`（逐日 `{date,equity}` JSON 数组引用）。候选和父本都必须有共同期初锚点和完整同日历，不能靠删行改变年化分母；期初现金必须一致。未核实完整账户的代理曲线不冒充账户原件。
- `research_segment_input.v1`：`experiment_id`、`subject`（本次结果／观察原件引用）、`contract`、`candidate`、`parent`。将它绑定到原计划或产物中；不能将别的候选的 pass 文件借来使用。

```text
python -X utf8 -B engine/research_walkforward.py evaluate --input <input.json> --out <segment.json>
python -X utf8 -B <segment.json.scorer.py> verify --report <segment.json> --expected-input <原input.json>
```

输出连同评分器源码封存；复核重新校验输入、运行身份、日历、参数、权益哈希并重算全部结果。三字段自报 pass、改过的指标、借用报告、缺日／不同锚点均不能通过。该工具检查可比性，不替代数据来源与账户核账真实性的独立复核。既有连续曲线分段也不消除既往数据暴露。

## 5. 线上批次对照：描述性入口

```text
python -X utf8 -B engine/research_online_ab.py --incumbent <已关闭旧版批次目录...> --candidate <已关闭候选批次目录...> --out <comparison.json>
```

仅支持具备原 BATCH、D、O、冻结 ENGINE 和 EXPORT／PILOT_REVIEW 的结构／旧 ML 接口；其他线不能仅改目录名伪装接入。读取原冻结引擎核验来源、关闭状态和账本；拒绝重复目录／批次／决策、跨组共享身份、复用同一账户证据充样本，以及组内混版或跨组评价／成本口径不同。新旧调度与 Harness 不能同时变。

主指标显式统一为账户改进；使用 `--require-segment --segment-index <index.json>` 时，两组都要求**账户改进且分段通过**。index 按 O 文件 SHA256 映射到 `{input:引用,report:引用}`。读取时重验报告，并绑定当前 O、当前账户评价证据和账户合同；账户负结果即使分段通过也不算成功。缺验证保留未知，不根据看到的数据临时切换成功定义。

输出恒为 `diagnostic_only`。决策数是描述记录数，不是独立样本量；同一研究树、反复筛选和未经事前分配的批次不能套二项区间后宣布方法获胜。比较需要采用或回退结论时，回到既有 H1—H5 的冻结真实任务试点。延迟含等待，不能冒充完整资源成本；缺成本也不能证明提效。

## 本次明确保留的判定

H3 保留原配对全部完成、原通过项不退化、完整成本不增加且存在严格优势的规则；每项已知成本和可确定下界先检查硬预算，其他缺项不能掩盖超限。失败／未知的关键检查不能被其他案例的胜出抵消。prospective_pilot 仍需完整成本，未知则回退；不接受未实施的 `decision_rule` 放宽字段。

RRSI 的未观测路径仍保持未知，不用“悲观惩罚值”冒充执行证据。保留原候选池与兄弟假设，继续用既有 frontier 接口有界逐项选择；本次不改并发提交语义。Claude 分支中的统一固定年份胜数、16／8 例、4 个候选、强制异模型家族、统计多数替代硬检查及自动选新版均未作为默认规则采纳。

这属于工程修复和兼容工具增量。登记共用版本不等于模型方法试点通过，也不宣称 RRSI 已带来真实研究改进。
