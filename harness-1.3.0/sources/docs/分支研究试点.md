# 分支研究：候选池与真实选择试点

2026-10-15 P1：新增可选择的 `bottleneck_evidence_cost_v1` 与 `shadow-frontier`，格式、排序与反馈链见[运行手册第 11 节](研究调度运行手册.md#11-2026-10-15-p1具体选题与方法反馈)。旧 `least_served_family_v1` 保留为原规则和影子对照；以下旧规则说明仍适用于原批次。新规则仅在下一合法未冻结边界显式绑定选择合同，不改写现有冻结件，不因本次维护启动真实试点。

效果评价沿[验收标准](研究验收标准.md)的`evaluation-20261013-v1`。候选池覆盖是防遗漏的准备提示，不是成绩；进入下一未冻结批次的候选须在原PLAN中说明本批经济问题、区分解释及成本依据，未入批项沿原池保留暂存理由。禁止靠改family、虚报ready或删去备选操纵顺序。新规则实现通过不等于方法优势，仍需原有界试点和同预算前瞻证据。

2026-09-23，MS004。用户已要求把偏线性研究改为多方向分支研究。本次先改变候选发现和具体问题选择；当前冻结实验继续使用其原程序、规则、表达和判据。多方向在研不等于多个完整账户同时运行。

## 1. 先生成一组，再选择下一项

每线维护一个可以跨批次接续的假设池。默认保留 6–8 个活跃假设，覆盖至少 3 个有依据的机制族；同一个假设的来源检查、模型拟合和账户检验使用同一 `hypothesis_id`，各步骤有独立 `id` 和 `question`，不得计成三个独立假设。已关闭、延后、缺数据和失败项保留，不能通过重命名消失。

首次拓展候选的预算是最多 30 分钟：复用完整机会池和已有知识，比较至少三类不同机制的来源、竞争解释和反证，形成最便宜的区分检验。结构线可从交易参与与价格关系、历史路径与相对环境、选择与资金使用中寻找确有证据的方向；ML 线分别考虑新增信息、目标与学习方式、预测到实际动作的映射。它们只是检索方向，不能被当作已经成立的假设。已有失败只关闭其原表达及证据支持范围，不封死整个机制族。

池中区分 `ready`、`needs_evidence`、`waiting_dependency`、`deferred`、`closed`。有机制依据但待核对字段的设想可以进入池；没有来源支持的名词清单不算候选。只有 `ready` 项可以派发。若预算用完仍不足，保留实际数量、已比较的机制/来源、淘汰理由及一个有界的补充动作，在准备时间继续补充；不能每次仅复述“缺 5–7 项、不凑数”。不强迫等待凑满才执行已有有效问题。

优先复用原 `CANDIDATES.json`、`PLAN.md` 和候选规格，不新建研究 CURRENT。新增机器读取的池版本采用 `research_frontier.v1`；旧冻结件只读，新版本引用旧身份、闭合结果及新增证据。非当前分支可在等待期间准备；完整账户仍按真实单决策接口逐项执行，两条研究线继续独立运行。

## 2. 具体候选如何被选中

试点规则 `least_served_family_v1` 在就绪且依赖合法的具体候选中选择：最近最多六个已派发候选里，该机制族被选择次数较少者先；再按事前的信息价值等级从高到低、预计成本等级从低到高、稳定候选 ID 排序。等级均为 1–3，信息价值 3 最高、成本 1 最低，须写判断依据；它们不是收益预测或成功概率。当前批次的决策自动计入，同线前批最多六份决策引用在边界冻结，不通过换批次清空分支历史。

这是一条可检验的初始规则，不声称最优。它让有依据、已就绪的不同方向先获得检验机会，再逐步深入。一个观察可有多个不同子问题；程序允许从已观察的非叶节点继续分叉。依赖缺失只排除相关候选；候选可执行性不能由名字相近或其他候选通过来代替。修复保持原问题编号；有效经济失败不以 follow 方式改参数救活。

每份实际 `D*.json` 保存选中候选 ID、假设 ID、机制族、候选规格哈希、全部可选项的排序与未选项的原因。结果登记同时核对候选 ID 和问题编号。来源/身份有问题时停止受影响实验、保留原证据；不要把它伪装成经济反证。

## 3. 最小文件格式与检查

以下是格式说明，示意来源必须换成真实的绝对路径和 SHA256。实际候选可在原文件中补字段并另存版本，无需复制长篇方案。

候选规格至少有：`id`、`hypothesis_id`、`family`、`question`、`mechanism`、`falsifier`、`data_clock`、`first_test`、`stop_rule`、`budget`、`source_evidence`。`data_clock` 写清交易决定时可知的数据和标签何时成熟；`source_evidence` 引用原记录。待补证项同样写出具体缺口，不能把拟议接口或不存在字段写成已就绪。

新规格的实验卡与单向引用按[研究能力改进规范](研究能力改进规范.md)第 2、6 节，复用上述原字段或 PLAN，冻结件另立版本。旧规则的 schema 和 frontier_pilot 字段不变；新选择器只增加运行手册第 11 节明确定义的合同与 SPEC 字段。check-frontier 通过只证明原池格式与引用合法，新规则的依据与排序再由 shadow-frontier 核对。

池文件结构示例：

```json
{
  "schema": "research_frontier.v1",
  "branch": "structure",
  "generation_evidence": [{"path": "实际绝对路径/PLAN.md", "sha256": "实际哈希"}],
  "shortfall_reason": "不足六个活跃假设或三个机制族时的具体原因；充分时可为空",
  "replenishment_action": "具体补充来源、问题及预算；充分时可为空",
  "candidates": [{
    "id": "H01_SOURCE_V1", "hypothesis_id": "H01", "family": "auction_participation",
    "question": "唯一实质问题编号", "status": "needs_evidence",
    "action": "explore", "anchor": "root", "depends_on": [],
    "information_value": 2, "cost_class": 1,
    "rationale": "这个检验能区分哪两种解释，为什么先做", "gap": "尚待核对的具体来源",
    "spec": {"path": "实际绝对路径/SPEC.json", "sha256": "实际哈希"}
  }]
}
```

`follow` / `repair` 的 anchor 使用本批已观察的 `n0001` 等节点，且列入 `depends_on`。跨批次既有证据通过规格引用，并说明原父假设身份；新批次调度根节点不表示这是全新的经济假设。closed / deferred 不计活跃假设；多个步骤使用同一假设 ID。规格改变另立版本，禁止重跑已关闭或未知身份。

```powershell
python -X utf8 -B engine/research_scheduler.py check-frontier --branch structure --frontier <新池文件>
```

本命令只验收格式、来源绑定和数量，不执行实验，也不证明假设正确。

## 4. 下一批边界接入，一次三次决策的小试

1. 当前批次先用其冻结对照目录的 `ENGINE.py` 完成 next / observe / review / export；项目入口代码更新后不能混用旧批次的哈希。未结束或用户暂停的批次不切换、不恢复。当前若另有方法试点，先完成它。
2. 用更新后的项目程序及同线、同评分合同的既有开发 WORLD 运行一次实际 `cycle`，形成绑定新程序的对照。历史输入相同时可复用新程序已经产生的回执。保留旧版为对照；旧历史没有候选池，不能据此声称分支方法胜出。
3. 在下一份 `SCHEDULER_BOUNDARY.json` 沿用原字段，增加以下 `frontier_pilot`。仅当 cycle 为 `retain_incumbent` 时允许启动这个用户要求的未校准试点，避免和另一项获胜规则试点叠加：

```json
"frontier_pilot": {
  "rule": "least_served_family_v1",
  "max_decisions": 3,
  "initial_frontier": {"path": "新池文件的绝对路径", "sha256": "实际哈希"},
  "recent_decisions": []
}
```

`recent_decisions` 首次确实没有此类记录才为空，后续填同线前批最近最多六份具体候选决策引用。可另存新的池版本并在下一份 `CONTEXT.json` 增加 `frontier` 引用；已经派发的规格及历史快照不得覆盖。依赖可以按已核验结果更新；结果后改表达必须保留原失败并另立版本。

4. 按原接口 `start-batch`、`next`、`observe`。`next` 直接给具体候选，原实验协议绑定它；`OUTCOME_INPUT.json` 增加 `candidate_id`，`observation.question` 与决策一致。`pending_result` 仍只允许一个待回传决策；准备其他假设不受它阻塞。
5. 三次决策预算（含失败与修复）或原三问反思边界先到即收尾；不增加训练、经济账户、聚宽额度或付费权限。冻结规则和经济门槛不随结果变更。`frontier_exhausted` 时继续有界候选补充，或收尾已有结果；不绕过接口重复派发。
6. `review-pilot` 再 `export`，随后执行或引用同输入的实际 `cycle`。frontier 结果导出为开发诊断：v1 回放仅重放动作次序，无法检验当时没选中的具体假设，不允许改成 heldout 或借其分数宣称新规则有效。

## 5. 判断效果与回退

事前主要判据是：是否从至少两个真正不同的机制族取得可核验、能改变判断的结论；未选、失败和未知是否保留；同等预算下候选质量、完整周期与总成本是否改善。至少记录生成准备、等待、计算、核验、方法维护和沟通成本；缺失不是零。实际派发两个族仅是流程落实，不能代替可靠结论，更不等于收益改善。

程序给出机制覆盖、已解决问题、实验成本及未知；不会把覆盖数量自动判成提效。首次试点收尾生成回到原规则的 `NEXT_POLICY.json`，需要把真实记录与原方法按相同口径比较后，才能决定后续是否继续显式试点或采用。证据不足保留原调度；跨批次假设池及有界补充工作照常保留，不能退回“做完才重新想一个”。经济目标、原生核验和正式采用仍走原授权。

本次工程验收与真实试点分开：隔离检查能证明选择、依赖和回退逻辑工作，不能证明两线已经接入或研究已经加速。

## 6. 方向拓展与深挖收口（MS013，2026-09-26）

按 [MS013](../analysis/research_method_supervision_20260922/MS013_方向拓展与深挖收口.md)补充下一自然准备边界：在原最多 30 分钟准备预算内，优先把当前主链以外的一个独立方向推进到可执行的最小区分检验，争取至少两个不同方向可供选择。来源步骤 ready、机制/信息检验 ready、账户 ready 分开说明；只列多个名称或把来源/标签/核账拆成方向不算落实。需要真实来源、决定时点、固定表达、原对照、实现入口、事前主要判据、预算和停止条件。日常准备可自主取用知识库原文，无需等方法任务审查。

预算后仍不足，明确已比较的证据、具体依赖、补齐动作和重新进入条件；暂不可得的方向保留在 deferred/waiting_dependency，已有有效候选照常执行。不得为数量虚构 ready、重开失败表达或反复生成同一份待办。

原三问反思或批次边界增加一段方向判断：本阶段要改变的决定、已解决/未解决的解释、继续/收口/暂存及下一项有界证据。连续两个自然边界仍只延长准备和核验链、未改变判断时，默认降低该方向准备优先级并比较其他方向；当前正确性所必需的修复保留，不能跳过相关核验。复用不变输入、实现、判据及检查器的有效核验，不另建台账。

本补充改变候选准备和阶段收口，不热改选择器，不叠加第二个调度方法试点。先观察下一完整三问周期，方法效果及因果归因保持未验证；沿用第 5 节成本比较、质量底线与原规则回退。维护候选数量不能代替可靠结论或经济进步。
