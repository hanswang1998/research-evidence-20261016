## 2. 冻结、检验、分层决定

冻结源码、窗口、费用、初始状态、对照、有效信息时点与判据。只改变待研究机制，明确共同政策。测试尽量使用真实辅助函数和接口，模拟只放在外部边界；覆盖应通过和应拒绝的案例，不能以“全部拒绝”作为可靠。

身份、来源、费用、现金、持仓、时序由程序核对；意义、反证和取舍由研究者判断。正确性修复、开发／选型收益改善、风险修复取舍、独立确认与采用分别记录；填写字段或预检通过不证明机制有效。按年度与右尾集中度解释连续账户，不继承旧父本收益或把固定状态反事实当资金路径。

检查与纠偏执行[研究调度提示词](研究调度提示词.md)第 4 节的检查时机、偏差分类、影响限定、复验和结束条件。

需要模型协作时，DeepSeek仍按明确任务辅助实现、测试和排错，主助手负责选题与裁决。简单数字核对不反复召集模型投票；有实质分歧时再做不同证据视角的复核。

## 3. 经验与反思

在原实验记录中分开写“事实及来源字段”“解释与反证”“下一步”。事实注明父本、窗口、分母及证据；模型解释不自动变成事实。出现摘要与原始字段冲突先回查来源，保留更正，不把结果未知当作负收益。不得把非即时成交类别直接当市场模式，或把少数活动次数称作收益不可能性的证明。

反思频率、提前触发和实际比较按[研究调度提示词第 3 节](研究调度提示词.md#3-调度改进反思后决定是否换规则)。调用、等待、代码修复、离线调度评测、流程维护不单独计轮。反思交付是具体更新了哪个判断、如何改变优先级、下一步为何能区分可能性；也允许有证据地维持原路线，不为凑反思强行换方向。

实际 cycle、同输入回执复用与缺口处理按[研究调度提示词](研究调度提示词.md)第 2、3 节。实际比较、评测等级及保留／回退依据写回原记录，不以文字替代执行；离线工作遵守现有授权，暂停不自动恢复研究。

## 4. 唯一状态与提交边界

[主交接](../analysis/yjj_n14_strict_limit_baseline_20260914/ITERATION_HANDOFF.json) 的 `current` 是新流程唯一当前状态；其他原字段为历史兼容，不再用于授权。实验状态、执行授权、版本与验证状态独立。通过 `engine/research_control.py` 更新执行和结果指针，使用版本号及单写入锁；不要用历史的局部更新脚本覆盖当前段。轮数与反思不按每份账户机械加一。

新提交统一使用 `research_control.py run --plan <新计划>`，真实 `jq_backtest.py` 入口、浏览器启动前与唯一点击前均检查；不允许靠缺参数或关闭环境开关绕过。`check` 和 `status` 只读。检查失败返回非零；预检不是“打印 False 也算成功”。源码、合同、收据、验收文档哈希、参数、授权范围、提交预算、并发占用与重复身份须通过。

任务先登记再调用，超时、异常和退出码 0 都不直接证明平台终态；按原身份收取并提交有证据的 reconciliation，未知不重提、不退预算。点击与暂停更新共用短锁：暂停先完成则不点击；已经点击的请求不自动取消。锁忙或过期须核实处理，不自动删锁、重试提交。

执行状态、有效授权与剩余提交预算读取主交接 `current.execution_by_line.main_strategy`，本文不保存运行状态快照。提示词或流程修改不构成恢复研究；需要恢复时保存已有真实用户指令、工作区、预算和有效期，再显式登记授权，不编造确认或反复使用旧恢复收据。已授权范围内自主推进，不为每个调度动作重复索要许可。主策略新提交支持免费完整 Tick 开发账户；Rust 的分钟采集和对齐仅接受控制器已审核的源码与窗口。两者均不支持付费导出、积分确认、自动采用、定时及实盘。旧回测结果继续读取，旧提交脚本不得直接重跑；准备新版本计划时更新当前工具绑定，不修改旧冻结输入。

### 研究线与共享资源

主策略执行段为 `current.execution_by_line.main_strategy`，Rust 工程为 `current.execution_by_line.rust_replay`；各自记录授权、暂停、尝试与事件。`current.research` 仍只保存主策略研究结论，工程结果不能覆盖它。历史 v1 执行记录已按审核归属迁移，原计划、收据和结果不改；冻结旧文件仅通过迁移时登记的精确哈希识别归属，新计划和恢复收据都必须带 `research_line`。

各线 `max_submissions` / `max_inflight` 只约束本线；`current.shared_resources.max_inflight` 约束所有线的实际未结束提交总量，同槽位和重复身份仍全局排重。默认状态查询只披露本线，实际提交时才读取 `--shared` 摘要。共享上限、槽位、未知结果和短锁冲突须逐动作说明，不能扩展为等待另一研究线完成。

用户明确暂停研究仍按其范围执行。批次完成导致的提交暂停、收据尚未登记或收据预算耗尽，只限制对应提交；已有用户授权内的分析、隔离候选、计划冻结继续进行。已有明确继续指令准确登记为本线收据，不要求用户反复确认同一范围。收据字段是本地执行约束，不能称作平台账户额度；不能通过任意改字段扩大用户授权。

版本变化本身不是阻塞。读状态一次即交付；实际共享文件写入使用短锁与版本校验，发生版本冲突后重新核对相关字段再更新，不等待整个工程静止，不重提身份或结果未知的任务。隔离产物的写入不等待另一线结束。
