# 高涨幅计算指引：Polars＋Parquet

新增或修改写入链条执行[研究产物治理](研究产物治理.md)，本文只保留本线计算与缓存的特殊要求。

自 2026-09-20 起，按用户“以后都用 Polars＋Parquet”的要求，高涨幅研究线后续的表格计算统一使用 **Polars**，计算用明细和中间表统一使用 **Parquet**。本指引适用于新写、修改及后续重新调用的计算链条；只迁移当前任务实际涉及的部分，不要求先改完历史实验。

本指引只规定计算方式和文件格式。研究问题、样本、交易时序、费用、裁决门槛及暂停／恢复仍按当前授权和原协议执行；修改指引本身不启动研究。

## 计算方式

- Python 保留任务编排、文件管理和小型元数据处理；筛选、连接、分组统计、均值／中位数、排序及窗口计算使用 Polars 原生表达式。
- 大表从 `scan_parquet` 进入，尽早选择所需列并限定日期、标的和样本；优先保留惰性计算，按需汇总或写出。不要先把整表转成 Python 字典／列表或 pandas 再计算，也不要用逐行 Python 回调代替可表达的列运算。
- 时间序列计算须显式指定标的分组、排序键及并列记录的处理方式；连接需核对键的唯一性和匹配数量。不能依赖分组返回顺序，也不能因换引擎改变买前可得时点、样本母数或缺失处理。
- 抽样、随机数和 Polars 不适合的数值内核可继续使用 NumPy：先由 Polars 筛选和汇总，只交付必要的小数组；保持冻结的种子、抽样顺序、精度及统计定义，在协议／实现说明中写明用途。这不是把大表运算退回逐行 Python 的通道。
- 独立复算仍需独立的构造及原始记录核对；统一使用 Polars 后，重复调用同一个汇总不能代替独立验证。

## 文件格式与旧数据兼容

- 新生成的计算用明细、中间表及大结果表写为 `.parquet`，默认使用 Zstd 压缩、级别 3。不再同时保存一份内容相同的完整 JSONL／CSV；人工检查只导出必要的小样本或汇总。
- 协议、状态、来源清单和小型结果摘要继续使用 JSON／Markdown；追加式事件日志继续使用 JSONL。它们不是本指引要求改成 Parquet 的明细表。
- 已冻结的 JSONL／CSV 和外部来源原件保持原身份。下次实际需要读取时，用 Polars 按明确的字段类型转换一次，在隔离派生目录建立 Parquet 缓存；不覆盖、删除原件，不批量搬迁无关历史。
- 缓存旁保留简短来源记录：原路径及 SHA-256、转换实现及版本、字段类型、行数、主键／排序规则、Parquet 路径及 SHA-256、核验结果。同一来源及转换定义复用同一缓存；来源或定义变化时生成新版本，不静默覆盖。
- 证券代码保留字符串和前导零；日期／时间、复权方式、单位及缺失语义按原协议保留。收益和价格计算保持原有精度，原为 Float64 的字段不降为 Float32；不把空值、NaN、停牌或失败记录统一填零。
- 大表按当前查询需要选择分区，避免每轮复制全部历史或生成大量小文件。只保留必要的派生表；清理原证据仍需单独的明确授权。

## 首次接入与核验

1. 从当前实验的实际输入、输出及调用方确定迁移范围。旧冻结源码保留；需要修改时形成新的实现身份，按原实验约定更新对应输入／输出清单和读取方。已有缓存不能仅凭扩展名认作有效。
2. 转换后核对行数、字段类型、键、缺失及失败计数，并完整读回比较转换前后的字段值和约定顺序。新旧计算对照须覆盖本次决定依赖的分组、统计量、抽样结果与最终判断；独立复算要求保持原协议标准。
3. 计数、样本身份、分类及裁决要求一致；Float64 统计量事前固定容差，默认相对与绝对容差均为 `1e-12`。若原协议更严格，沿用原协议；出现差异先定位原因，不通过放宽容差、修改样本或门槛来完成切换。
4. 核验通过后，后续同一链条使用 Polars＋Parquet。输入、实现和判据未变且无新疑点时复用已有核验；改算法、字段、版本或数据口径时，只复验受影响部分。

旧实现只在必要的迁移对照或原协议要求的核验中调用。后续任务不能因沿用旧脚本而默认继续 Python 逐行扫描；应在本次获准范围内先完成所需链条的适配。读取／计算提速不改变实验本身的研究或验收结论。

## 环境与性能记录

- 使用本线隔离依赖环境。运行前确认解释器能导入 Polars，并记录实际 Python、Polars、NumPy 版本及线程配置；依赖缺失时先补齐隔离环境，不静默回退计算引擎。
- 当前已验证组合为 Python 3.13.8、Polars 1.44.2、NumPy 2.2.3；现有解释器为 `C:\veighna_studio\python.exe`，独立 Polars 依赖位于 `%LOCALAPPDATA%\CodexBench\polars-e154-20260920\site-packages`。使用该组合时须把该依赖目录加入本次进程的模块搜索路径；不要把共享 Python 环境默认视为已安装 Polars。
- 初次接入记录转换成本、文件体积、读取／统计耗时及峰值内存。比较速度时固定相同输入与口径，说明缓存是否预热，区分首次转换、常态计算和含启动的总耗时；线程数按当前可用资源设置，不机械固定为 20。
- 已完成的 E154 对照见[速度报告](../analysis/polars_benchmark_20260920/REPORT.md)、[冻结测量计划](../analysis/polars_benchmark_20260920/PLAN.json)和[结果与一致性记录](../analysis/polars_benchmark_20260920/RESULT.json)。基准脚本可参考读写与分组写法；其中种子、列结构和统计定义属于 E154，不直接套用到其他实验。

本指引的默认方式仅约束高涨幅研究线；主策略与独立 Rust 回放工程仍使用各自入口和执行约定。
