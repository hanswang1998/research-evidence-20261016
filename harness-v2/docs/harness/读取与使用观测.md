# 指引的按需读取与使用观测

`guidance-20261016-v1`。目标与评价、研判与选题的常规入口改用两页核心；原目标、验收、能力规范保留原字节，继续作为细则和旧冻结件依据。更新入口不恢复暂停、不扩研究或预算，不要求重跑。两页核心承接原约束，不更改选择器和评价程序。

## 读取什么

| 动作 `--phase` | 实际返回内容 |
| --- | --- |
| `goal` | 目标与评价核心 |
| `select` | 目标与评价核心、研判与选题核心 |
| `evaluate --stage information` 或 `engineering` | 目标核心、资格／实质增益、失败分类；按阶段判定，不启动账户 |
| `evaluate --stage economic` | 上项加账户顺序、费用与数值口径 |
| `confirm` | 目标核心、实质增益、重复开发／独立确认、三种证据区别、账户与数值细则 |
| `reflect` | 两页核心、结果学习与判词范围 |
| `method` | 两页核心、方法比较、独立性、实际 harness 接入规则 |

只有需要深入定位经济失效时加 `--detail judgment.diagnosis`；其他指定章节可通过 `read --help` 查询。同一次来源只读一次；输出过预算直接报错，不静默裁剪核心。这里限制字符数，不冒充模型 token 或费用测量。阶段语义仍由 Agent／复核人判断，程序不证明读懂规则。

```powershell
# 路径与执行者替换成本次真实身份；用已有 PLAN 或批次目录，不新建研究总台账。
python -X utf8 -B engine/research_guidance.py read --phase select --line ml3 --run-dir <原批次目录> --actor <执行者>
python -X utf8 -B engine/research_guidance.py read --phase evaluate --stage economic --line structure --run-dir <原批次目录> --actor <执行者>
```

读取返回 `packet` 的绝对路径／SHA和实际 `instructions`。在原 PLAN／SPEC 绑定该快照，已读且未变时直接复用。仅在一个判断实际依赖某规则时，在该段保留返回的 `[guidance:规则ID:摘录哈希前缀]`；不新增逐轮填表，不为了计数堆引用。输出完成后：

```powershell
python -X utf8 -B engine/research_guidance.py record-use --run-dir <原批次目录> --packet <读取返回的packet路径> --artifact <原PLAN或结果路径> --actor <执行者>
python -X utf8 -B engine/research_guidance.py report --run-dir <原批次目录>
```

`record-use` 必须有该目录中已观测的读取／任务事件，并实际扫描指定产出中的精确引用，不接受 `used=true` 自述代替证据。没有匹配就记录零引用和语义使用未知。它只证明引用出现，复制标记并不能证明规则得到遵守。未改动的旧严格 schema 可在原报告中引用，不强塞新字段。

## 观测能证明什么

| 事件 | 真实证据 | 仍然未知 |
| --- | --- | --- |
| `reader_output` | 读取器读取并组装了哪些文档、SHA、行范围、摘录哈希、字符量和返回正文 | CLI退出后的宿主传输／截断、模型是否注意到 |
| `task_assembled` | 正文确实装入已保存 TASK，绑定完整指令SHA与长度；证据摘录保留范围、截断和哈希 | 是否发给模型、模型是否理解或执行 |
| `output_citations` | 指定产出在记录时的SHA、出现引用的行号与规则ID | 引用是否用于正确判断、行为与经济效果 |

身份字段是调用方声明，不是平台认证。无事件表示未观测，不能断言没读。`Get-Content`、`rg`、编辑器及聊天里粘贴的内容不会被本工具自动监听；不读取账号或模型日志，不监控其他目录，不新增自动化。日志哈希链用于发现意外损坏，不是防篡改认证或绩效评分。

每个原运行目录只使用 `guidance/EVENTS.jsonl`，快照按内容哈希复用；日志不复制全文，引用原产出。短锁避免并发覆盖，已有残缺行或链损坏报错且保留原件，不自动删除／补零／覆盖。读取失败不记成功。需要修复时针对损坏范围处理。报告里的历史产出引用代表当时观测，若要核对当前文件，须核对其记录SHA。

## 已接入的程序与后续验证

新 `research_harness.py` 的 `harness-init` 自动冻结读取器和两份指引快照：反思取 `method`，候选生成取 `select`。两种任务实际包含正文并记录 `task_assembled`；提交提案和生成结果时自动观察对应输出引用。校验／重建 TASK 不重复计读。日志故障会在返回值中明确给出 `telemetry.status=unknown`，任务原件和其中的内容清单保留，不把观测故障当研究失败。

可在新计划中用 `guidance_input: {reflection: {path, sha256}, generation: {path, sha256}}` 绑定读取器预先生成的快照；新开发边界核对原文与范围，不能伪造或省掉核心。前瞻试点沿开发比较已固定的两份快照，不随全局文档更新改变实验条件。基线和候选使用同一指引，费用／模型／评分／选择器保持原合同。

从冻结目录的 ENGINE 发起后续轮次时，默认沿用该冻结包捕获的指引；不会因目录位置变化误读全局新规则。需要更新规则时从当前中央入口在合法新边界冻结。原 REVIEW 分开记录不可变产物与观测日志在裁决时的字节；后续部署继续追加日志，不回写旧裁决。

已冻结 ENGINE／HARNESS、旧批次与三篇完整细则都不修改。结构／旧ML之外的专题线可立即使用独立读取器；是否真的经过此入口，以本线日志和输出为准。新入口接通、实际模型调用、跨线采用和方法提效分别验收，本次本地维护不替代后续真实研究试点。
