# Harness v2 运行说明

2026-10-16，用户要求的 harness 修订。下一合法未冻结边界生效；在途冻结件、旧 ENGINE、旧 REPORT 与旧哈希都不变。改动理由与证据见 harness-v2/CHANGES.md，本页只说怎么用。

## 每批的固定顺序

1. **先读本线状态摘要**，再按摘要指向的原件补读。
2. 按[调度提示词](../研究调度提示词.md)第 1 节选题。若边界冻结了 `branching`，同一可见状态会开出 2—3 个兄弟决策，每个检验不同机制。
3. 执行器命令用计时工具包裹；生成、复核、沟通阶段用 start／stop 记时。
4. 核账后，控制器运行滚动验证，Agent 只读遮蔽版结论。
5. `observe` 时绑定成本回执与滚动验证裁决；结果在原状态之外写统一的 `outcome` 类别。

## 本线状态摘要

`engine/research_line_digest.py` 按配置从本线 STATE 中只取决定下一步的字段，列出全部已关闭表达，附最近几次反思；每段摘录都带原件路径和 SHA256，并有总字符预算。示例配置为 `config/line_digest/ml3.json`。在 2026-10-16 的 ML3 STATE（388,984 字节，182 个键）上，摘要为 14,632 字符，列出 58 个已关闭表达。

```powershell
python -X utf8 -B engine/research_line_digest.py --config config/line_digest/ml3.json --root <项目根目录> --out <本批>/LINE_DIGEST.md
```

其他线复制该配置，改 `state`、`fields`（JSON pointer）、`closed.key_pattern` 与 `reflections.glob`。摘要只用于定位，裁决、授权与预算以原件为准。harness 评价案例中，把对应时点的摘要作为第一项 `evidence`。

## 计时

`engine/research_timing.py` 在工作发生时记录时间，写出不可覆盖的计时文件，`seconds` 字段可直接被成本回执读取（`seconds_path: "seconds"`）。

- `run --event-id … --phase execution --out … -- <命令>`：包裹执行器命令，原样返回命令的退出码。
- `start` ／ `stop`：用于不是子进程的 Agent 工作（generation、verification、communication、maintenance）。
- `receipt --cost-contract … --subject <D*.json> --timer … [--none <phase>] --out …`：组装 `research_cost_receipt.v1`。没有计时的阶段写 `null`（未知）；只有确认完全没有该阶段活动时才用 `--none`（写 `[]`）。同一资源（默认 agent 或 compute）上时间重叠的两个计时拒绝组装。

计时记录的是该资源上的活动时间，不是等待时间，也不是墙钟总时长。

## 滚动验证

`engine/research_walkforward.py`。默认合同：完整可见 2020—2022，验证折 2023、2024、2025；至少 2 折胜出、平均差不小于 0、各折回撤不超过 20%；遮蔽验证数字。

```powershell
python -X utf8 -B engine/research_walkforward.py default-contract > <边界目录>/WALKFORWARD_CONTRACT.json
python -X utf8 -B engine/research_walkforward.py evaluate --contract <冻结合同> --candidate <候选逐日权益> --parent <父本逐日权益> --out <Agent可读>/WALKFORWARD.json --detail-out <控制器专用>/WALKFORWARD_DETAIL.json
```

逐日权益接受 JSON 列表 `[{"date": "...", "equity": ...}]`、带 `equity_curve`／`daily`／`series` 的 JSON 对象，或含 date 与 equity（或 total_value／value／nav）列的 CSV。2026-01-01 起的行一律不读，并在 `sealed_rows_ignored` 中计数。`--detail-out` 的完整数字放在 Agent 不读取的位置；这是约定，须如实记录是否被打开。

## 结果统一分类

`engine/research_outcomes.py` 的八类：`improvement`、`negative`、`risk_limit`、`information`、`engineering_failure`、`evidence_gap`、`not_executed`、`unclassified`。新记录直接写其中之一；旧记录用 `classify` 尽力映射，判断不了的记 `unclassified`，不猜。在 2026-10-16 的 4,137 行台账上，映射后 `unclassified` 占 3.8%，主要是只写了 completed、看不出账户结论的记录。

```powershell
python -X utf8 -B engine/research_outcomes.py ledger --csv <台账CSV> --show-unclassified 20
```

## 在线交替对照

`engine/research_online_ab.py` 比较两组已关闭批次（旧版与新版交替运行）。每组至少 30 个观察；主指标为滚动验证通过的改进率（观察带滚动验证裁决时）或改进率，次指标为未出结论率。区间为 Newcombe 区间。结论只说明开发期研究效率，不是独立经济确认。

```powershell
python -X utf8 -B engine/research_online_ab.py --incumbent <旧版批次目录...> --candidate <新版批次目录...> --out <报告>
```
