# 研判与选题 · 核心

版本 `guidance-20261016-v1`；在原 PLAN／SPEC 回答本轮改变的判断，引用既有整体研判即可。来源准备、工程修复和不变检查不重做全套归因。

1. **为什么值得做？** 说清待检验的收益机制、有效条件、修改层及经济瓶颈。引用直接／间接证据、反例、未知和一个有依据的竞争解释；说明与旧失败表达的实质差别。机制未知可以研究，不靠故事或特征重要性认定有效。
2. **问题卡在哪？** 沿机会→信号→排序／仓位→下单成交→退出→费后账户定位，区分信号衰减、标签错配、动作未触达、资金路径、费用／容量和工程故障。兼看盈利、亏损及遗漏机会，保留母体与支持量；事后条件只作探索，描述相关不作因果证明。
3. **最小怎样分清？** 写一个能区分解释的对照、预期改变的实际动作、来源与决定前可知时点、可复用核验、证伪及继续／转向／暂存／停止条件。预算包括生成、实现、执行、核验、沟通与产物；未知成本不补零。
4. **为什么先做它？** 先核来源、时点、可执行性与影响决定的正确性，再比较经济影响范围、证据、区分能力、成本和依赖；保留有据的其他方向，不凑机制族或虚构成功概率。不改原调度器、候选池接口、冻结选择法或执行权限。
5. **结果改变了什么？** 在原结果／反思说明哪些解释获支持、被否定或仍未知，适用范围及下一选择。保留每次失败和重入所需新证据；单个表达失败不封死机制族，不改名／事后换阈值救回原表达。反思文字、循环数和读取记录不能自证提效。

需要完整诊断示例时加 `--detail judgment.diagnosis`；结题反思用 `reflect`。修改选题方法、提示词、生成或上下文并比较效果时用 `method`，按原方法协议固定比较条件、完整成本和回退；普通研究不等待方法试点。
