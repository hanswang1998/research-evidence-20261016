## 1. 真实研究：选择并完成下一步

你负责提出能改变判断的问题和候选机制，并用本批冻结的调度规则安排研究。只读取当前问题需要的状态与原证据，不按轮重读全部历史。

初始调度规则 v1：先处理会影响当前决定的身份、在途结果和正确性未知，再按预期信息、证据支持、成本与依赖选择实验。这个次序只处理真实相关的缺口，不把常规检查变成每轮仪式，也不把所有工程故障永久排在经济问题之前。

1. 明确当前未知、不同结果会改变的决定、最便宜的有效检验。既有证据足够时直接形成结论；不为增加尝试数重复实验。
2. 从合法动作中选择：复用证据、按原身份补证、修复可定位故障、深入现有机制、探索新机制、保留或停止。新机制可以没有历史结果，必须通过真实检验获得结果。批量候选先固定范围并排重；依赖未满足的父子动作不能同批并行。
3. 区分实现故障、来源／身份不确定、证据不足、有效经济反证。一次可修复错误不抹掉此前有效结果；缺记录不计零收益。有效失败按冻结表达及证据支持的范围关闭，不能换阈值、方向、窗口或名字挽救原裁决。
4. 比较有价值的少数动作，给出所选动作的证据、预期区分结果、成本与停止条件。兼顾有根据的新机制与有效分支延伸，不用固定比例机械分配；证据不足时保留未知，不捏造概率或收益上界。
5. 在现有授权与预算内冻结实验，走原执行和验收入口。新调度批次先按运行手册冻结质量计算、程序和规则；选择下一步时实际调用 `next`，把决策件引用绑定进新实验协议。源码、时序、账户口径及原判据照常核对。批次内规则固定；安全或正确性问题可以停止受影响批次，保留偏离原因及原版本，不能静默绕过选择器或改规则挽救比较。
6. 在原实验记录中分开写事实、解释、下一步。结果按第 4 节检查后，用 `observe` 登记真实裁决、成本和证据。决策件与结果件保留调度版本、理由、父节点、可见观察、依赖、可见时间上界及故障类别；未知不填零。修复沿用问题编号，不增加独立经济问题。`pending_result` 只表示等待该身份结果，不能重跑或把全线标为阻塞；不额外创建一套正式当前状态。

新信息出现后重复以上步骤；是否继续由本次任务范围和当前执行授权决定。普通查询或维护完成后结束，不因这套循环自动转入研究。

### 1.1 批量候选准备与有界并行

结构线与 ML 线各自维护下一批候选池，替代“上一问结束后才从头准备下一问”的安排。当前用户已明确要求两边开展批量候选准备；在途冻结实验保持原版，新候选进入后续批次。这里改变候选准备与编排，候选来源和信息增量按第 1.2 节核对；原目标、数据边界、费用和采用标准继续适用。

1. **先形成可审阅的候选池。** 默认争取一次准备 6–8 个有依据的候选；不足时交付实际数量与缺口，不以改名字、密集扫阈值或重跑已关闭表达凑数。用本线现有证据排重，声明各候选研究族和相对旧反证的新信息。准备阶段不读取尚未产生的结果，也不把计划记为已完成研究。
2. **每个候选写清同一组字段。** 唯一编号与研究族；待回答问题及支持证据；父本和唯一改动面或事前声明的组合；数据／标签／特征及版本；真实前置依赖；最便宜的有效检验与完整账户判据；预算、停止条件和输出隔离位置；状态及未就绪原因。候选规格在见到本批结果前保存版本与哈希；结果后修改另立版本，保留原方案和全部尝试。
3. **一次准备共用部分。** 验收仍有效的输入、只读缓存、执行模板和检查器只准备一次，各候选用独立配置与输出。先说明哪些步骤可直接复用、哪些变化必须补验，再准备隔离实现及必要的边界检查；不逐候选复制整套文档、重复全量验收或立即启动拟合／经济回放。依赖尚未成熟的候选标为等待依赖，其他候选准备继续。
4. **分开候选池与调度批次。** 在本线 `candidate_portfolios/<新批次ID>/` 保存 `CANDIDATES.json` 和简短 `PLAN.md`，原交接只引用其路径与哈希。这是准备产物，不是新的全局 CURRENT 或执行授权。候选池可跨多个三问调度批次；每个独立实质问题单独计数，不能把 6–8 项打包算一问、重置计数或遗漏失败。
5. **把并发写成可验收的计划。** 首批计划每线最多 2 个本地计算任务，两线整机合计最多 4 个；记录每任务库线程、内存与磁盘预算，并计入仍在运行的任务。候选有真实依赖时顺序执行，同一账户内事件顺序不变。v2 起，批次边界可冻结 `branching: {siblings: 1—3}`：同一可见状态一次开出最多 3 个兄弟决策（`D0005/D0006/…`，带 `sibling` 组号），各自执行、各自 `observe`，结果可乱序回填；整组回填完才开下一组。兄弟分支须检验不同机制，不能是同一表达的参数变体；它们共用原请求预算，不增加聚宽提交数量、额度或付费权限。这样记录下来的是一棵树而不是一条线，离线回放才有可比的分支。仍不能靠忽略 `pending_result`、开多个绕行批次、编造命令或把未完成结果提前登记来绕过；已有合法的账户内分片和两线独立运行照常接续。
6. **减少等待并衡量整轮时间。** 计算或远程核验等待期间，可准备无依赖候选；必要收取与当前核验照常完成。新记录分别保留准备起止、就绪、派发、计算结束、核验结束时间，以及已测 CPU／I/O 阶段、峰值资源、排队原因与复用范围。并发耗时按批次墙钟时间计算，不能把各任务耗时之和当作等待时间。缺项保留未知；比较同样预算下的可靠结论覆盖、候选质量与完整周期耗时，不能用更多提交、删核验或只汇报胜者制造提速。

准备与结果写入遵守[研究产物治理](研究产物治理.md)：公共数据只引用一份有效版本，交接不嵌套复制历史，大明细不重复导出多种完整格式；文件粒度按实际查询需要确定。预计产物量级和实际新增文件数／逻辑字节分别放入原 PLAN 与完成回执，由本次写入过程计量，不新增逐文件报告或全库扫描。

本轮准备交付应指出首组选中候选、可并行集合、真实依赖、待实现接口和预期节省发生在哪一段。前瞻实测之前标为未校准编排试点；批量准备完成、并发接口验收、实际并行运行和效率改善分别报告。

## 2. 离线评测：只沿已记录的研究路径回放

你负责检验调度规则。使用 `engine/research_scheduler.py cycle` 及冻结世界执行真实比较，操作见运行手册。只有文字推演时标记诊断，不填写伪造分数、节省比例或通过回执。输入不足时记录实际程序返回、具体缺口与下一批最小补齐动作，不能持续用“尚无回放器”代替调用已存在的入口；无关的已授权独立工作继续。

- 先固定研究片段、父本和依赖、数据／账户口径、评估器版本、成本口径、候选规则及评测预算。不可比较的片段分组，不拼成统一收益或效率数字。
- 将开发片段与保留片段按时间或完整研究族划分，避免高度相似的父子变体跨组。若规则制定者已经看过保留答案，明确该检验不是独立前瞻证据。
- 规则执行只接收已揭示的观察、合法动作和预算。最终报告、后续 `current` 状态、未揭示结果、包含胜负提示的名称不能作为决策输入；评测器可保存答案，不能把答案投影给规则。交易信息时点与实验结论可见时点分别检查。
- 选择动作后才揭示其真实记录，且主要父节点及其他信息依赖必须满足。缺结果、缺可见时间或不支持的分支不按相似实验填补。v1（默认）把这类选择记为未知／不支持，比较不完整；`--replay-semantics v2` 时按悲观口径计：不揭示任何结果、不增加已回答问题，但计一次请求，并按该世界已观测节点的最高成本计费，所以不可能借此显得更省。一条回放中这类选择超过一半时，该比较记为覆盖不足、不可比较。该分支可转为后续真实探索候选（v1 把任何一次这类选择都判为整个候选不可比较，导致 2,227 个候选只因此被拒）。
- 先检查身份、正确性、泄漏和证据等级，再比较获得可靠结论的成本、同预算保留的有效结果、误关分支与未解决缺口。有效否定须有原问题和判据支持；不能靠全部拒绝或大量提交刷高分。
- 成本包括规则生成／修订、离线评测、真实实验、采集核验；按实际可核算项报告，缺失不计零。并发按真实资源和等待测量，不奖励无用批量。没有达到目标的记录，就报告未达到。
- 输出所用版本与证据、各规则实际走过的节点、比较结果、不支持覆盖及成本未知。没有执行回执就保留未评测；不把模型解释当成运行结果。发现身份、泄漏或计算问题时按第 4 节处理，受影响的比较未经复验不能用于选优。

这里回放的是研究决策历史。`local_replay` 等行情／账户回放的策略初筛结果，不能替代本节的调度比较，也不能替代聚宽原生连续账户或策略独立验证。

## 3. 调度改进：反思后决定是否换规则

你负责改进研究安排，保持任务目标、底层研究模型和评估口径固定。每三个实质问题必须产生一次实际比较回执，周期如需放宽至五个须在批次前冻结；重要反证或连续低信息结果可以提前触发。输入、规则和评估器完全未变时引用已有回执，不重复跑相同对照。必须检验，不强制改版；没有可核验优势时保留当前版。

1. 指出本轮想改善的具体问题，例如重复投入、过早放弃修复、只围绕一个机制微调。先核实相关历史是否完整，是否已有可复用的评测；不要先建庞大历史库。
2. 默认比较当前规则和最多两个有明确差异的替代规则。事前固定修改面、修订次数及成本上限，在已授权范围内完成；规则只改变分支优先级、补证／修复选择、批次安排和停止逻辑。不得改写评分器、交易门槛、原实验判词或授权。
3. 按第 2 节先 `export` 完成的批次，再实际运行 `cycle`；初版按开发回放反馈生成最多两套有明确差异的可执行规则，保存冻结件、全部轨迹和比较报告。保留当前规则及失败版本。生成候选只使用开发反馈，选定候选后核对保留片段；看过反馈又用于改规则的片段必须转为开发，不能继续称其独立。
4. 有可核验改善才选出下一版；并列或证据不足时优先保留当前版。`--replay-semantics v2` 时的试点资格：开发世界上严格优于父本（质量、已回答问题或请求数，已知成本不增），且至少一个干净的保留世界（prospective、无限制）上不退化。开发世界带“人工覆盖”等限制不再阻止资格，只有保留世界必须干净。成本未测全只记 `cost_unknown`，不阻止资格，试点必须实测。回放分数较高只支持历史内选优，不证明未来更好。固定下一版内容与哈希、依据、适用范围和真实小试判据，再安排下一批；没有足够回放证据但需尝试新规则时，明确标为未校准的真实试点。
5. 小规模真实对照沿用同口径目标、资源和评估器，事前冻结 `pilot_criteria`，完整记录结果与总成本。结束时运行 `review-pilot`；不达标会生成指向原版的 `NEXT_POLICY.json`，下一批按其回退，保留失败。新轨迹核验后加入历史。提示词按“固定目标与边界 → 本批规则 → 当前选择所需证据”披露，不随单个结果重写全局提示词。

调度评测、模型调用和工程修复不增加经济研究轮数。它们的结论与策略正确性、开发期改善、总目标及正式采用分别记录；执行状态和研究当前状态仍只有原权威入口。

## 4. 检查与纠偏：修复后再验证

这是本项目对双循环的工程补充。形成“执行 → 检查 → 分类处理 → 复验 → 继续或回退”的反馈，不新增一套状态台账，也不把修复循环当成经济研究。检查针对会改变当前决定的事实与差异，不要求每轮全量重审。

1. **何时检查。** 动作前复用仍有效的边界与输入核验；新结果用于裁决、调度选优或后续依赖前检查相应原证据。发现身份、正确性、未来信息或冻结协议偏差时立即处理，不等到 3—5 个问题的集中反思；规则试点结束后还须核对事前效果判据。
2. **凭什么判断。** 对照冻结协议、实际输入／源码版本、原始结果与执行回执，核实关键指标、时序、费用和未知。优先使用已有校验及独立复算，不只复述生产汇总；同一助手声称“已修复”不算复验。修改检查器后须用独立参照核对受影响判据，不能用被一起放宽的检查器自证通过。缺少必要证据或可运行核验入口时保留证据不足，继续无依赖的已授权工作。
3. **先分类再纠正。** 按下表处理，不把所有不理想结果都当作应修复的错误。

| 偏差类别 | 纠偏方式与判断边界 |
| --- | --- |
| 来源、身份或证据缺口 | 按原身份补证或核对；未知保持未知，原任务不因超时重复提交，不借用别的实验结果 |
| 实现、计算或执行偏差 | 定位原因，另存修复版本并保留原失败；若修复改变经济表达、信息口径或判据，则另立实验，不能视为原比较已修复 |
| 有效经济反证 | 按原判据关闭固定表达；负结果本身不是程序错误，不通过换阈值、窗口或方向“纠正”为通过 |
| 调度重复、成本失控或低信息投入 | 进入第 3 节比较替代规则；正常改版在批次边界进行，必要时先停止受影响批次，不边看结果边改原规则 |

4. **限定影响并保留更正。** 标明哪些结论与下游依赖受影响，以及仍可复用的证据；受影响结论不能当作已验证结果用于选优、机制判定或推广，可照实记录无效或证据不足，无关且已授权的工作可继续。原记录追加缺陷、原因、修复版本及依赖影响，不覆盖冻结件或删除旧裁决；正式状态更正仍走原受控入口。规则回退只能选择仍有效且适用的既有冻结版，没有合格旧版则保留待核验。
5. **复验后才解除限制。** 针对原故障与受影响依赖执行必要核验，保留应通过和应拒绝的案例，避免靠全部拒绝获得“通过”。复用输入、实现、判据均未变化的有效检查；有改动、失败或新疑点才扩大核验。记录实际入口、输入／版本、结果与原证据；缺陷修复、复验通过、经济有效和调度提效分别裁定。仅相关复验通过后，才解除对应限制；真实研究能否接续仍取决于当前授权。
6. **按证据接续。** 明确纠偏范围、产物并记录成本。代理自设时长／修复次数只是进展检查点，不自动终止已授权工程修复；负责人据原因继续修复、换实现或移交，复验合格后接续验证。用户预算、真实资源／外部依赖及有效经济反证按原证据处理，历史冻结件与失败不倒改。检查通过且无新疑点即进入下一步，不重复检查；可复用经验写回原实验／反思记录。

## 5. 交付与接续

复用原实验或反思记录，简要写清：当前问题与选择的动作；规则版本及评测等级；已知事实、成本和未知；相关检查结论、未闭合偏差与复验依据；停止／继续的证据及下一步。没有偏差时引用有效检查即可，不填虚构的纠偏记录。依据真实证据标记为“规则提案／文本初始规则”“回放已评测”或“真实小试已评测”，不凭填写字段升级。

进入真实研究前，按本批冻结协议接续；切换任务或上下文后只补读当前问题、规则版本与必要依赖。已有有效授权无需按动作重复确认；暂停、费用、扩源和采用边界仍由原执行流程及本次用户指令决定。

## 6. 披露与阻塞判断的范围

每次先确定本次任务及研究线，再披露本线当前状态和当前动作所需证据。主策略只用 `current.execution_by_line.main_strategy` 与 `current.research`；Rust 工程批次的暂停、收据、完成条件和旧记忆不能充当主策略第一动作。状态查询报告一次观察时刻即结束，不等待版本静止、不追查其他 Agent 会话。

仅在当前实验明确依赖某工程产物，或实际提交/同文件写入遭遇共享资源冲突时，才披露该依赖。阻塞须附具体动作、所属线、资源或文件、当前证据、解除条件及可继续的工作。资源冲突只延后受影响动作，用户已授权的独立分析和候选准备继续进行；未知提交不重提，用户明确暂停的工作不恢复。

检查披露流程时记录：本次问题、实际读取路径、无关研究线读取、阻塞依据及其适用范围、用户已给出的继续指令是否被遗漏。出现串线先修正范围，再按冻结条件比较；离线程序回归只能证明路由及控制逻辑，不能声称模型已按新规则运行或披露效果已提升。

## 9. 开发期滚动验证、在线交替对照与计时（2026-10-16 v2）

依据 2026-10-16 审计的可选做法。第 1—3 条在边界显式冻结对应合同或批次后才生效，属于试用；第 4—6 条只增加记录，不改变判定。在途冻结件按原版完成，不重判旧结果。

1. **决定看滚动验证段，不看同一开发窗口上的再次领先。** 约 1,100 个账户候选在同一 2020—2025 窗口上反复比较：结构线中位年化 275%（最高 336%），ML3 中位 299%，固定基线 316%。唯一样本外的 ML2 2026-01-05—09-30 原生账户中，E1002J 年化 57.6%（开发期 306%），H543 91.2%（开发期 294%）。在产生父本的同一窗口上继续追高，主要是在挑噪声。新经济候选在边界冻结 `walkforward_contract`（默认：完整可见 2020—2022；2023、2024、2025 各为一个验证折，至少 2 折胜出、平均差不小于 0、各折回撤不超过 20%），由控制器在核账后运行 [research_walkforward.py](../engine/research_walkforward.py)。Agent 只读遮蔽版结论（每折通过与否和粗略区间），完整数字存放在 Agent 不读取的位置；这是约定，不是技术隔离。冻结了该合同的批次中，`valid_improvement` 必须同时满足原账户评分和滚动验证通过，否则按 `valid_negative` 登记，`observe` 会强制检查。
2. **这仍是开发证据。** 2023—2025 已被大量查看过，现有父本在这些年份上的通过只是弱证据；遮蔽的作用是减缓新候选继续过拟合。独立确认仍按[验收标准](研究验收标准.md)使用未参与选择的数据，2026 保持封存。结构线与旧 ML 在 2026-10-04 前约 214 个账户的评估窗口为 2020-01-02—2026-07-24，2026-10-14 还有一次误读 2026 公司行动记录，这两条线谱系的 2026 并不完全干净，确认时须披露。
3. **方法比较优先用真实交替批次。** 新旧调度规则或 harness 版本在相邻批次交替使用，各积累至少 30 个观察后运行 [research_online_ab.py](../engine/research_online_ab.py)：主指标为滚动验证通过的改进率（有验证结论时）或改进率，次指标为未出结论率（工程失败 + 证据缺口）。离线回放只作初筛。同时尽量跑一组“旧版加同等额外预算”（多采样或多重试）的对照（`--control`），并用 `--candidate-overhead` 计入产生新版的成本：预算对齐后，自动进化常常胜不过简单重试。
4. **成本由程序计时，不靠事后手填。** 执行器命令用 `research_timing.py run` 包裹，Agent 的生成、复核、沟通阶段用 `start/stop` 记时，每个决策用 `receipt` 组装五阶段成本回执。v1 台账 4,137 行中只有 139 行有计算结束时间。
5. **每批先读本线状态摘要。** 用 [research_line_digest.py](../engine/research_line_digest.py) 生成；只在摘要指向的原件上补读，不重读全量历史。ML3 每批 33—48 分钟，64—76% 的工具调用在读文件，账户计算本身约 1.5 分钟；STATE.json 约 39 万字节，摘要约 1.5 万字符。
6. **结果统一分类。** 新记录在原状态字段之外写 `outcome`，取值为 [research_outcomes.py](../engine/research_outcomes.py) 的八类之一；原始描述保留。没有统一类别，就无法比较两个版本的命中率。
