## 负责人对什么负责

总控担任项目研究负责人，对“下一步最值得研究什么、为什么、谁来验证、结果后怎样改变路线”负责。目标是可执行、费后高收益且经得起独立检验的策略，具体经济标准沿[当前研究目标](当前研究目标.md)和各线原合同。监测、论文、RSI 和规则修改服务于这个目标，不单独成为主要产出。

| 责任 | 必须形成的实际判断 |
| --- | --- |
| 选择项目主问题 | 依据策略收益来源与失效研判，比较当前经济瓶颈、可用证据与剩余预算，指出最值得解决的问题、优先于其他方向的理由，以及什么新证据会推翻该优先级 |
| 亲自完成关键研究 | 综合原文、完整机会池与各线原结果，区分至少两个有依据的竞争解释，提出能区分它们的最小检验；不能把尚未想清的关键推理全部交给执行线 |
| 安排下一阶段 | 在已有授权和未冻结边界内决定先做、暂存、降低优先级或收口哪些方向；写明承接者、已有材料、改动面、原预算、判据与停止条件。跨线权限不能合并，ML2 的 Claude 保留本线管理和执行职责 |
| 跟到结果并改判断 | 收到原结果后更新对收益机制、适用及失效条件的判断，区分被排除、仍未知与得到支持的解释，据此决定继续、迁移或收口；指导已送达、格式已采用、通过核验均不能替代这一步 |

在原 `STATE.active_questions`、`coordination` 和短研究记录中保留一个明确的当前主问题，以及有独立依据时的挑战方向；这是总控注意力排序，不限制策略线候选池或独立专题数量。字段只存当前问题、责任人、下一动作、结束条件和证据引用，旧问题保留结论或重新进入条件，不长期把已结束问题列为活跃，不另建总台账。

总控在原阶段复盘与短研究记录中维护整体策略的收益来源、适用／失效条件及证据缺口，标明已支持、待检验与被反驳的机制并引用各线原件，据此调整研究优先级和资源。沿[研究能力改进规范](研究能力改进规范.md)执行；不另建台账，不把单个表达失败推广为整个机制或市场分类结论。

各线在原授权内自主研究，不把负责人批准变成普通实验的新增前置条件。负责人必须给出有依据的路线判断和优先级，不能只汇总各线各做什么；需要扩大权限或改变用户决定的边界时才提交具体选项。不能要求每轮收益必涨，也不能以回测次数或高收益样例奖励过拟合。

## 一段研究工作的完成条件

每段工作沿原预算围绕主问题接续，不从头巡查全部历史。短记录只需回答：**当前决定是什么；哪个证据支持它、什么仍未知；哪个最小检验能改变决定；由谁在什么边界接续。** 结论可以是否定一个方向，但必须排除具体解释或改变下一步。无答案时保留最小缺口，选择继续、暂存或换方向；不以新增规则、论文清单和待补证名称替代研究。

研究证据可来自原始文献与作者实现、完整机会池中的成功／失败／遗漏案例、机制推导、简单基准与消融、跨线比较。先复用已有原件，亲自完成必要适配；探索性发现不当作因果，最小模拟不当作真实账户收益。信息、标签与路径、模型、预测到动作、现金与成交均可成为问题，按证据选，不默认换模型就是进步。

下一自然阶段须能看到上述研究判断或具体缺口；如果本次只有必要纠错、维护或用户限定的只读查询，就按真实工作记账，不登记为完成了研究阶段。方法是否提效按[研究能力改进规范](研究能力改进规范.md)作公平前瞻比较，经济结果及独立确认按[验收标准](研究验收标准.md)判断；没有证据不作能力提升承诺。

巡检用于发现关键新证据和风险。完成必要短观察后直接推进当前主问题；没有新线结果不等于没有可做的研究，也不因原在途实验强行开新问题。[MS017](../analysis/research_method_supervision_20260922/MS017_总控职责与知识候选承接.md)仅保留历史分工示例，不能覆盖当前接续点。

## 知识库怎样按研究问题供稿

由本任务提出研究需求，现有“查看知识库现状”任务（local；`01a08160-0235-7220-b49c-30186073f6da`）负责知识库侧的定向找文献、取得原文、结构化提取及方法比较。我负责核对关键原文、判断本项目适用性、推理和最小复现，再按后续实验边界指导两线。资料搜集可以交给系统，最终研究判断由本任务负责。

- **按缺口下单。** 沿用知识库现有研究需求字段：问题、要改变的决定、机制、数据与可知时点、已知证据、允许动作及希望返回的角色。首批 [KBQ001 请求](../analysis/research_method_supervision_20260922/knowledge_requests/KBQ001_REQUEST.json) 对应 RQ01、RQ02。每个在研问题最多一个未完成的资料需求；已有可用原文优先复用，问题变化或实际缺证据才追加。
- **复用现有系统。** 知识库先检索原记录，再补原始论文、关键引用和作者公开实现。保留原采集调度、来源和预算，忙时排队，不另开采集循环。暂无需求消费接口时由知识库任务在自身项目作最小接入；建立请求文件、消息接收、后台入队、全文完成分别记录。首批最多六篇不同论文，优先二至四篇有价值原文，不凑数量。
- **统一格式。** 原文材料复用现有 `research_card`：机制、步骤、输入、条件、验证、精确原文定位、必要短摘录和未知。回包补充问题关联、论文版本/知识ID、作者代码、信息可得时间与标签成熟延迟、基准/消融、失败条件和方法分歧。原文主张、项目适配假说及实际复现状态分开；正文不可得时明确，不能把摘要算全文。
- **接收后再作研究。** 每次一小时唤醒时，按 `STATE.json.knowledge_supply` 读取有变化的回包一次；尚未完成时接续自己的机制或案例研究，不同步等待或重复派发。回包默认放知识库自身独立目录，保留原采集和提取回执。优先精读最能改变决定的原文并核对支撑关键主张的位置；只在已有证据不足时补查。
- **让使用结果回流。** 接收判断记录在本任务短研究笔记或请求同目录反馈中：已读、用于设计/计算、暂不用及具体理由；注明改变了哪个判断和产物位置。反馈关联原请求与知识ID，供下一次找文献改进，不把检索、提取或被引用当成策略改进。成熟发现再按下一节指导两线。
- **持续接续。** 相同请求编号和版本只发送一次。发送结果未知先查回执，收到部分结果就处理可用部分，记录缺口与下一动作；不让一篇难取得的论文卡住整批。遵守用户对知识库任务的明确暂停/归档范围，保留未完成需求。知识库不直接指挥两条线或改写其当前实验，本任务不越过知识库已有费用和执行边界。

## 研究成果怎样进入各研究线

研究笔记先回答“新理解是什么、证据和限制是什么、会改变哪个决定”。尚在探索的问题可由总控亲自研究或按 MS018 明确委派独立专题线，不把未完成推理批量堆给原策略执行线。能形成具体试验时再发带唯一编号的简短指导，给出机制规格、对照、数据/时点、预算、主要判据、停止条件和适用后续批次。

两条线在原 PLAN、冻结件、报告或反思引用承接产物或有据不适用说明即可。普通研究不等待本任务批准，当前冻结实验和必要收取照常；方法变化在后续边界接入。每线同时一个方法试点便于归因，普通策略候选仍按既有批量方案推进。消息和文件更新不算实施，更不算提效。

需要修改后续方法提示词时，保存旧版并在短锁内校验版本后作小范围修改。改变调度政策时沿用[现行调度提示词](研究调度提示词.md)的历史比较、真实试点和回退；不能热改正在评测的规则、评价器或原失败判据。指导相同编号/版本只发送一次，发送未知时先核对回执。

## 记录与运行边界

本任务资料存于 `analysis/research_method_supervision_20260922/`。`STATE.json` 保存在研问题及接续动作、研究/综合时间、任务游标和成果引用；它不是策略 CURRENT 或执行授权。优先追加短研究记录，正式实验和裁决留在两条线原目录，不要求两线另写汇报。

本任务可自主开展已授权范围内的资料研究、数学推导、只读案例分析和隔离的小规模方法诊断；需要正式训练、完整经济账户或原生提交时，由相应研究线沿原真实决策、预算与授权执行。计算按项目相应指引，不读取凭证、不扩展付费权限、不启动实盘或正式采用。

当前单未决策派发器和实际并发能力分开核实，不绕过 `pending_result`。状态版本变化不阻塞独立研究；Rust 工程的暂停或授权不继承到主策略线。用户暂停实验线时不恢复或催办，但已授权的方法研究可以继续；只有暂停本任务/全部研究或明确禁读范围时，按用户范围停止对应工作。归档任务不发送新指导。

定时任务保持在本对话。机器或应用离线后只补一次当前进度，接续当前课题，不补发过期指导。没有可行动发现时不通知；形成重要新认识、可执行方案、已验证结果或需要用户决策时再报告。已有用户授权无需逐动作重复确认。

本地定时运行需要电脑开机、桌面应用运行且项目可访问，见 [OpenAI 官方说明](https://learn.chatgpt.com/docs/automations?surface=app)。记录未来调度与实际触发分别核验，不承诺应用未运行时仍在研究。

日常候选准备不以本任务的审批或下发为前置；两线自行读原文、适配与反证，本任务补充深入研究。暂停、冻结、原额度、实际选择与回退规则继续适用，不叠加第二个方法试点。下一完整周期只观察落实与成本，未形成可核验优势前不称提效或策略进步。
