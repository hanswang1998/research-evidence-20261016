# 主策略机器学习计算指引：Polars＋Parquet 与 Rust

按用户“以后都用 rust，或者之前说的速度快的分析框架”的要求，主策略机器学习线后续新增、修改或再次执行的计算链条采用以下默认分工。实际环境、准入结果和版本从本线权威交接的 `compute_policy`、`compute_preflight` 引用读取。

## 默认分工

- 大表读取、筛选、连接、分组、排序、窗口计算和标签整理使用 Polars 原生表达式；计算明细和中间表使用 Parquet，默认 Zstd、级别 3。
- 从 `scan_parquet` 开始，尽早限制日期、证券和列，优先惰性执行；不要把整表转为 Python 字典列表或 pandas 后逐行处理。
- 行情回放、撮合、状态递推和循环密集的核账优先复用已验收 Rust 内核；新增 Rust 检查器须有自己的来源、构造和等价验证，重复调用生产内核不能冒充独立核验。
- Python 用于任务编排、小型元数据、模型库接口和必要的 NumPy 数组；训练前由 Polars 明确样本及特征顺序，再交给既定模型。更换计算引擎不自动更换 LightGBM、模型参数或研究表达。

## 公共数据和并行

批量候选准备遵循[本线任务提示词](../analysis/yjj_ml_research_20260921/RESEARCH_PROMPT.md)及[共同调度约定](研究调度提示词.md#11-批量候选准备与有界并行)。一次准备候选与共用数据，候选个数和运行并发数分开；当前单未决策接口未扩展前，不假定多个候选已获派发。

- 同批共用清单在验证冻结 SHA-256 后加载一次，以已验证内容建立只读缓存，供各路径使用。缓存键绑定来源哈希、类型、转换实现及版本；任何一项改变均失效。不得只按路径、文件名或扩展名信任缓存。
- 独立账户和路径可有界分片并行；同一账户内保持事件顺序。记录实际工作进程和库线程数，避免进程与线程嵌套过量；不机械沿用单线程，也不默认占满机器。
- 性能比较使用相同输入和计算范围，分别记录首次转换、读取、计算、校验及总耗时，说明缓存预热与内存。快速汇总不能与完整逐交易核账相比后宣称提速。

## 精度、来源与验收

- 保留证券代码前导零、主键、排序与并列规则、完整机会母数、原买前可得时点及标签成熟时间。缺失、未成交、来源未知和未平仓状态独立保留，禁止统一填零。
- 沿用原冻结的价格单位、Decimal／浮点精度及舍入规则。不得因迁移改变费用、逐笔现金、仓位或交易顺序；Float64 不降为 Float32。
- 首次迁移核对完整身份、行数、类型、字段值、缺失和状态计数，并对当前决定依赖的分组与结论做新旧一致性验证。身份、分类和裁决精确一致；数值沿用原协议容差，未规定的普通 Float64 汇总默认绝对及相对容差 1e-12；不得放宽既有更严格标准。
- 原冻结源码和原始证据保留。旧 JSONL／CSV 在当前任务需要时转换一次，隔离保存 Parquet 缓存及来源回执；协议、状态和小摘要继续 JSON／Markdown，追加事件日志可继续 JSONL。
- 已完成且输入、实现、判据不变的核验结果直接复用。新增数据或实现改变只补验受影响范围；必要独立核验和经济完整账户门槛仍按原协议执行。

## 适用范围

本指引适用于主策略机器学习线，不调整其他研究线的状态或授权。历史冻结实验保留原版本；下一次实际调用相关链条时完成所需适配，无需先重写全部历史代码。环境应先验证能导入 Polars，并记录 Python、Polars、NumPy、相关原生内核及线程配置；缺失时处理明确依赖，不静默退回逐行 Python 大表计算。

参考：[Polars 惰性计算](https://docs.pola.rs/user-guide/concepts/lazy-api/)、[查询优化](https://docs.pola.rs/user-guide/lazy/optimizations/)。
