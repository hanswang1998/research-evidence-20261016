## 论文与实现核验

《Dream-RSI: Recursive Self-Improvement through Evolving Worlds》，arXiv:2609.14858，当前为 2026-09-14 提交的 v1 预印本；作者机构包括 Google、Google DeepMind、马里兰大学和弗吉尼亚大学。[论文记录](https://arxiv.org/abs/2609.14858)；[作者项目页](https://www.dream-rsi.com/)。

方法是把真实探索轨迹保存成可逐步揭示的树，低成本比较不同分支选择和停止策略，再将胜出策略用于下一轮真实探索，继续扩充历史。底层模型保持固定；改善的是研究调度代码。回放只覆盖实际记录过的路径，不能生成未知实验结果。[作者方法说明](https://www.dream-rsi.com/#method)

同模型 Lasso 对照中，研究调用由 550 降至 317，六个留出任务的平均运行时间由 3587.1 降至 2931.0 毫秒。按表中数值计算，分别减少约 42.4% 和 18.3%。宣传中的约 162 倍比较使用不同底层模型，不能单独归因于调度方法。自相关任务也未超过固定探索对照。[论文实验](https://arxiv.org/html/2609.14858v1#S4)

复现有两点待补齐：作者完整代码与复现脚本尚未发布；主文的最佳分数、调用惩罚和并行奖励目标，与附录 B.2 的 Pareto 曲线面积及并行惩罚写法存在差别。目前可以自建方法原型，不能声称已精确复现作者系统。[官方发布计划](https://github.com/zhengkid/Dream-RSI#release-plan)；[论文附录](https://arxiv.org/html/2609.14858v1#A2)

本轮通过 GitHub API 核对 main 全量文件树，未发现框架源代码。核验时间为北京时间 19:00，树 SHA 为 `4149ea9181ab1db80f85717ffda2c9f0f130e85b`。README 中 arXiv 尚待发布的旧提示，与已经存在的论文记录不一致；论文版本以 arXiv 为准。

## 最值得借鉴的改变

以下均是针对本项目的设计判断，尚待实验验证。

现有死法库与反思记录主要帮助研究者理解过去。可增加一层检验：面对同一段历史，只给调度器当时已知的资料，观察它是否更早发现关键错误、是否把额度继续花在低价值分支、是否错过值得修复的实现问题。

例如，一条排序表达未改善账户表现，另一条表达因来源身份不一致而无法判断。调度器应区别处理：前者按其冻结合同裁决；后者优先核对原任务身份，不能把“结果未知”归成经济失败，更不能因超时另发一次。随后检验这种调度是否减少成本、同时保留可靠结论。

建议将执行层能做的事情与研究层的判断分开：

| 调度动作 | 输入与输出 | 衡量价值 |
| --- | --- | --- |
| 复用已有证据 | 指向既有原始字段，回答本轮问题 | 是否避免了重复实验 |
| 补齐现有实验 | 按原身份收取、核对或补证 | 是否消除了会改变判断的未知 |
| 修复实现问题 | 保持实验问题和原判据，修复可定位错误 | 是否恢复了有效检验能力 |
| 深入一个机制 | 明确父本、待改变项和预期区分结果 | 是否产生新的、可靠的结论 |
| 探索新机制 | 解释与已有表达的差异和所需数据 | 是否扩大有根据的研究覆盖 |
| 停止或保留 | 说明证据支持的关闭范围 | 是否减少无效投入且未误杀有价值分支 |

这些动作是本地适配方案，范围比论文中的分支选择更广。首版应只选择其中已有可核验历史的动作。

## 最小可验证试点

### 1. 从一小组完整历史开始

优先选同一父本、账户口径与评估器版本的一组已结束研究。可以从 20—30 个候选实验开始筛选，最终数量取决于证据完整性；至少覆盖有效改善、有效否定及可修复故障。无法还原依赖的条目留作检索材料，不能补造回放节点。

每个节点最少需要以下信息，尽量由已有文件自动提取：

- 实验身份、主要父节点、其他上下文依赖，以及同族关系。
- 提出问题、开始实验、结果可被研究者获知的时间；提交时间不能替代结果可见时间。
- 冻结源码、数据窗口、资金与费用口径、评估器版本及原始证据指针。
- 当时已知的观察、故障类别、最终验证事实与仍未知的字段。
- 实际研究调用、模型用量、平台等待、本地计算成本；缺失项保留未知。

树只能表达一个主要父节点；若研究吸收了其他分支的结果，必须另存依赖。回放时不能把尚未揭示的旁支结论偷偷带入候选说明。

### 2. 比较少量明确的调度方法

先用三个可解释版本验证回放器：固定顺序、按已有可靠结果继续、同时考虑故障可修复性与机制覆盖。每个版本都接受相同的可见历史、可行动作、成本模型和停止边界。

回放器按所选动作揭示已经记录的结果。不存在对应历史时标为“不支持回放”；不能填零分、猜收益或借用相近实验的结果。同一条研究路径的因果顺序必须保留。

比较多个完整研究片段，再考虑由模型修改调度代码。初版无需训练模型；模型只生成有限数量的候选调度规则，由程序执行和评分。模型修订成本也要记账。

### 3. 用独立于调度改写的片段检查泛化

按时间、完整研究族或完整研究片段划分调度开发集和检验集，同一父本的高度相似变体尽量同组。不能随机拆散节点，使同族最终答案进入开发材料。

若历史检验片段的结果已经被调度规则制定者看过，只能称为保留片段回放诊断。可信的前瞻验证需要先冻结规则，再观察其后的新研究。研究调度的留出检验与交易策略的独立验证是两件事；本项目已使用行情仍按 used_development 处理。

### 4. 再进入有限真实试验

离线结果足够支持时，在既有执行授权和预算下开展小规模真实研究对照。调度器产出的计划交给现有控制入口；它不自行恢复暂停、不改变验收文档，也不将开发期改善晋升为正式采用。

一次真实研究批次内保持调度代码和评分口径固定，结束后才修订下一版。新的真实轨迹再加入历史库，由此形成可审计的改进循环。

## 验收应回答什么

不建议以最高历史收益作为唯一调度奖励。正确性、身份和证据等级先构成硬边界；在可比较的有效结果内再比较质量与成本。

建议冻结这些评测问题：

1. 得到同一个可靠结论，需要多少次真实实验和多少总成本？
2. 在同一成本下，是否保留了有价值的改善、有效反证和必要修复？
3. 是否误把机械故障、缺失证据或来源不一致当成经济失败？
4. 是否使用了尚不可见的结果、重复提交，或者跨口径比较？
5. 改善是否跨多个片段存在，而非只记住某组历史实验的编号？

若历史中没有达到目标的实验，“达到目标所需成本”应记为未达到，不能造出节省比例。有效否定也要由预先固定的问题与证据标准判定，不能让“全部拒绝”成为刷高分的捷径。

并发收益按平台真实槽位和等待情况衡量；不要为了加分占用更多槽位。总成本包含生成调度代码、离线比较、真实实验和采集审计。研究调用减少不自动等于同等比例的费用或时间节省。

## 判断与边界

值得试验的收益是减少重复、错误归因和低信息投入，并让下一步研究选择可以比较。它并不增加行情信息，也不能由历史研究回放证明未来收益。

最大的前提是历史依赖足够完整。旧实验的源码即使固定，它当初的产生过程仍可能依赖当时的全部经验；换一个研究顺序，模型未必还会提出同一个候选。因此，离线回放只能筛选调度规则，后续真实研究仍需验证。

建议下一步交付一个只读原型及对照报告：明确哪些历史可回放、各调度方法走了哪些节点、花了多少可核算成本、漏掉哪些有效结果、还有哪些未知。先用这个结果决定是否接入日常研究，不先扩大框架和流程。
