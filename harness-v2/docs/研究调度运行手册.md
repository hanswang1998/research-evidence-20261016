# 研究调度运行手册

**2026-10-17 v2 可选项（显式开启才生效；默认行为与 v1 相同，旧 BATCH／ENGINE／REPORT 不迁移、不回写）。** `cycle --replay-semantics v2`：回放语义 `pessimistic_unobserved_v2`、成本未知不拒绝、试点资格只要求保留世界干净。边界 `branching`：兄弟分支。边界 `walkforward_contract`：滚动验证。具体见第 3、8 节中的 v2 段落和第 13 节。

2026-10-13评价接入：原评分器和冻结ENGINE不改字节，新未冻结PLAN／裁决遵循[验收标准](研究验收标准.md)的`evaluation-20261013-v1`。`quality`及`return_improved`是原开发数值，`observe`状态仍按程序要求记录；它们不自动授予实质增益、换父本或确认资格。原REPORT给出是否足以改变下一决定及证据，不增加第二套分数。不得为了匹配新文字而篡改已有分数、旧哈希或旧状态。

2026-09-22，运行接口 `research_scheduler.v1`。供正在执行主策略研究的助手使用；入口为 `engine/research_scheduler.py`。结构线使用 `structure`，机器学习线使用 `ml`，分别冻结、评测和接续。Rust 工程、高涨幅研究、查询和普通维护不进入此循环。

本工具已有可运行的在线决策、历史回放、候选规则生成、比较、批次冻结及试点回退。初版在一个小的可执行规则空间中修改分支优先级和延伸深度，由固定解释器执行；不是任意改写整个助手提示词，也不是模型权重训练。历史记录不足时如实保留原版。不同研究目标、评分器和证据等级不混成一个比较。

## 1. 当前运行批次如何接入

1. 完成当前已冻结问题及其必要核验，保持原策略、调度版本、授权和费用边界。不得把新规则倒填到已进行的实验。
2. 在下一批边界读取本手册一次。初次接入使用本分支的[结构线对照](../analysis/dream_rsi_runtime_20260922/structure_cycle_002/REPORT.json)或[机器学习线对照](../analysis/dream_rsi_runtime_20260922/ml_cycle_002/REPORT.json)。这两份是旧历史诊断，均保留初始可执行规则；不证明优于以前的文字规则。
3. 在自己的隔离工作目录准备 `QUALITY_CONTRACT.json` 和 `SCHEDULER_BOUNDARY.json`，运行 `start-batch`。使用报告目录的 `ENGINE.py` 可以严格复用已冻结程序；项目入口版本与冻结版本不一致时，程序拒绝混用。
4. 在原批次协议中绑定生成的 `BATCH.json`。原本的研究状态仍为唯一研究入口；只在原交接中保存这一批次引用，不另建一个全项目 CURRENT，不覆盖另一分支指针。

`SCHEDULER_BOUNDARY.json` 包含：

```json
{
  "branch": "structure",
  "status": "first_scheduler_batch",
  "affects_running_experiments": false,
  "quality_contract": {"path": "完整绝对路径/QUALITY_CONTRACT.json", "sha256": "实际文件哈希"},
  "evidence": [{"path": "上一问已完成的实际回执绝对路径", "sha256": "实际文件哈希"}]
}
```

后续边界使用 `previous_batch_completed`。这些是输入格式示例，必须由当前事实填写，不能直接把示例当回执。文件引用一律为绝对路径和实际 SHA256。可用 `engine.research_scheduler.reference(path)` 生成引用。

```powershell
python -X utf8 -B engine/research_scheduler.py start-batch --report <本分支REPORT.json> --boundary <SCHEDULER_BOUNDARY.json> --out <新的调度批次目录>
```

程序不启动模型、不提交回测、不改暂停或授权。分支是否可以开展真实研究，仍由已有授权和原执行控制决定。

## 2. 先冻结质量计算，禁止主观填分

2026-10-04起，下一未冻结评分批次采用[MS028](../analysis/research_method_supervision_20260922/MS028_风险约束下收益优先与评分接入.md)的 `research_quality.v2 / account_profit_v1`：正确、同窗、同资金、同成本／撮合的完整账户，回撤≤20%时按累计费后净收益率排序，超限分数为`-1-回撤`。20%包含边界；同窗相同本金下累计收益与利润排序一致。独立确认另定协议，不能由该分数推出。

使用MS028目录中的QUALITY_CONTRACT_TEMPLATE和ACCOUNT_COMPARISON_TEMPLATE完成一次薄适配。已有原核验有效则直接引用，不重建核账链；候选和固定对照的来源、日历／日期／资金／费用／成交摘要必须各自匹配。`check-quality`先验合同，`review-account`生成只读评分卡；`observe`把同一适配作为grade_evidence，自动保留评分卡并拒绝与程序结论冲突的valid_improvement。风险修复取舍在评分卡单列，不能在报告变成收益提升。

首次迁移最多占用原准备预算内10分钟。当前BATCH／ENGINE／QUALITY仍冻结；自然结束后新评分链保留现行调度政策，按MS028第4节初始化，实际next/observe/cycle照常执行。不同quality合同的WORLD不得混评；没有新合同下的真实记录时用零观察diagnostic WORLD（quality=null）表达缺口，不能填写假成绩或把初始化当调度比较胜出。旧批次未结束或方法试点尚在进行时不得切换。

历史 `research_quality.v1 / joint_goal_margin_v1` 与 `risk_cap_return_v1` 保留兼容：前者仍按旧双门相对余量，后者仍按旧ML净年化目标计算。旧函数和冻结副本不重判。原格式及解释完整保存在[修改前手册](../analysis/research_method_supervision_20260922/MS028_delivery_20261004/before/docs/研究调度运行手册.md)。新评分不能只把旧年化字段重命名为累计收益，跨期或跨撮合结果不能混用。

输入收益和回撤用比例，利润用元，空缺保留null。信息诊断、实现错误、证据缺口不产生经济质量分。分数只是调度比较的一维；独立确认、执行和正式采用仍需原证据与授权。

RRSI政策仍比较质量、可靠结论覆盖、请求及完整成本，不支持的回放路径不能取得资格；全部成本未知不能宣称节时或提效。本次是用户目标变更，不是已验证的方法优势。

## 3. 每个新问题执行同一接口

下一批候选先按[调度提示词第 1.1 节](研究调度提示词.md#11-批量候选准备与有界并行)批量准备，结构线和 ML 线各用自己的 `candidate_portfolios/<新批次ID>/CANDIDATES.json` 与 `PLAN.md`。候选池记录选择范围、依赖、共用输入、执行模板及资源计划；它可覆盖多个调度批次，不直接作为本程序 `start-batch` 的边界文件。实现、模型拟合和完整经济账户的就绪状态要分开说明。

**v2 兄弟分支：** 边界含 `"branching": {"siblings": k}`（k 为 1—3）时，`next` 一次写出 k 个决策件并返回 `status=sibling_decisions`；非 frontier 模式下 k 个决策共用同一锚点和动作，由执行者给出 k 个不同机制；frontier 模式下取排序前 k 个不同假设。全部回填前 `next` 返回 `pending_result` 及 `decisions` 列表；`observe` 按 `decision_id` 接受组内任一决策，节点号跟随决策号（D0005→n0005）。k=1 与 v1 行为一致。k 受 `max_attempts`、试点 `max_requests` 与 frontier `max_decisions` 共同约束。

**v1 接口能力（未设 branching 时仍如此）：** `research_scheduler.v1` 一批只允许一个未回传决策，没有 `next-batch`、worker 池或共享本地并发租约。准备多个候选不需要占用多个 `next` 决策；实际执行时仍按本节取得唯一决策，并将选中候选规格的路径／哈希与决策件一起绑定进原协议。选择不符合返回动作时如实保留偏离，不能自动记为遵守。禁止为绕过 pending 拆出并发调度批次、伪造多候选已派发或把实验未完成写成终态。

后续并发接口须另行实现与验证，至少覆盖多在途身份、精确依赖、整机容量、逐项收取／失败隔离、按真实问题计数和反思边界；已有批次继续调用原冻结程序。接口未具备只限制跨候选并发执行，不阻塞候选准备或原有授权研究。运行记录实际证明并发后才称为已并行，计时证明改善后才称为提速。

准备 `CONTEXT.json`，只引用当前已知且实际使用的证据：

```json
{
  "branch": "structure",
  "context_complete": true,
  "evidence": [{"path": "当前问题或已知证据的绝对路径", "sha256": "实际文件哈希"}]
}
```

```powershell
python -X utf8 -B engine/research_scheduler.py next --batch <调度批次目录> --context <CONTEXT.json>
```

返回的 `D0001.json` 等决策件，绑定了程序、规则版本、可见节点、证据及所选起点：

- `explore/root`：提出一个有依据的新问题，仍做原排重和冻结。
- `repair/n...`：定位并修复指定节点暴露的实现问题，保持原表达和判据。
- `follow/n...`：沿指定节点的有效发现或尚未解决的信息问题继续。不能换参数救回有效经济失败。

把决策件路径和哈希写入新实验协议，按原研究执行流程开展。选择与真实执行必须一致；发生新的正确性问题而需要偏离时，可以处理，但必须记录 `decision_followed=false` 及原因，该调度批次随后结束为诊断。不能默默跳过选择器。

有未登记结果的决策时返回 `pending_result`，不会生成第二份指令。按原身份核验正在运行的任务，同时可以准备候选池内无依赖项；不要为解除 pending 重跑、重提或猜测结果。

结果经过原独立核验后准备 `OUTCOME_INPUT.json`：

```json
{
  "branch": "structure",
  "decision_id": "D0001",
  "decision_followed": true,
  "observation": {
    "status": "valid_negative",
    "quality": null,
    "question": "本批唯一问题编号",
    "resolved": true,
    "substantive": true
  },
  "grade_evidence": {"path": "原账户独立核验回执绝对路径", "sha256": "实际文件哈希"},
  "measured_seconds": null,
  "total_seconds": null,
  "evidence": [{"path": "实际裁决回执绝对路径", "sha256": "实际文件哈希"}]
}
```

```powershell
python -X utf8 -B engine/research_scheduler.py observe --batch <调度批次目录> --result <OUTCOME_INPUT.json>
```

`valid_improvement` 与 `valid_negative` 必须提供可核验的 `grade_evidence`。`verified_information` 表示已回答的信息问题，`implementation_error`、`evidence_gap` 保持 `quality=null, resolved=false`。修复沿用原 question 编号；不重复增加实质问题数。`measured_seconds` 只填实际测量范围，`total_seconds` 缺任何必要成本就保留 null。首次记录时给出保守结果可见上界；不能拿交易日期冒充研究结果可见时间。

## 4. 每三问必须形成一次实际评测回执

初始规则每完成三个实质问题返回 `reflection_due`，最多16个决策请求；实现故障不凑问题数，修复预算不会无限延长。反思周期只能在后续批次边界明确冻结为3至5问。

```powershell
python -X utf8 -B engine/research_scheduler.py export --batch <已完成批次目录> --out <新的WORLD.json>
python -X utf8 -B engine/research_scheduler.py cycle --branch structure --world <开发WORLD.json> --world <未用于改规则的保留WORLD.json> --incumbent <本批规则JSON> --out <新的对照目录>
```

`export` 后当前批次关闭。`cycle` 先冻结世界、程序、评分身份、当前规则与预算，执行当前版，再根据开发回放反馈提出最多两套有明确差异的规则并分别执行。输出 `CONTRACT.json`、`INCUMBENT.json`、候选版本、逐步轨迹、`REPORT.json`、`NEXT_POLICY.json`；保留失败和并列方案。初始规则与旧文字版不构成经过实测的等价替代关系。

回放只给规则看已揭示节点，合法选择为 root 或已观察的叶节点；选择后才揭示原记录的后续步骤。尚未揭示的依赖、没有记录的后续、未知结果都不能补造。初版单工人，不虚构并发加速。为了保守防止旁支信息泄漏，自动导出把当时全部可见观察作为依赖，可能缩小可比较范围；不能删依赖以制造优势。

保留片段用 `export --usage heldout` 导出；必须为真实未参与候选设计的完整片段。不得通过改 JSON 标签把已读历史变成独立检验；看过反馈之后的后续开发，该片段转入 development。结构与 ML 的世界不能混评，不同评分合同也不能混评。

相同输入、规则和评分器可引用已有真实回执。新历史则在本批收尾预算内做一次对照；不能连续几十轮只写“未回放”。记录不足时对照输出具体缺口，下一批先补最小记录，维持本线已授权独立研究。缺口不得变成 Rust 或另一研究线的全局阻塞。

## 5. 候选上线与回退

只有完整前瞻记录、固定质量计算、开发片段优势和保留片段支持同时满足，报告才产生 `eligible_for_bounded_pilot`；否则 `retain_incumbent`。前者只允许下一批小试，不自动改变活跃批次或正式采用。

候选试点的边界文件额外冻结 `pilot_criteria`：`min_quality`、`min_resolved_questions`、`max_requests`。判据来自本次需要验证的具体调度优势，先固定再运行，不能只写“感觉更好”。程序会限制请求预算，原策略验收仍照常执行。

```powershell
python -X utf8 -B engine/research_scheduler.py review-pilot --batch <已结束试点目录>
```

输出 `PILOT_REVIEW.json` 和 `NEXT_POLICY.json`。不达事前判据或偏离冻结规则时，下一版自动指向冻结的原规则；通过仅表示达到这一小试判据，不自动宣称全面提效。先复核试点、导出新轨迹，再进行下一次 cycle。将回退件绑定到下一批边界，不能继续使用已经结束的旧批次。

## 6. 成本、版本与异常

- 原研究授权、资金及采用标准不在策略可修改范围内；调度程序不会自行调用研究模型、回测或账户。
- 生成候选、回放、试点和人工准备的成本分别记账。程序记录本身耗时，但不会把它当成全部进化成本；早期维护用量未知仍明确为 null。
- 历史记录不完整的首次两个片段只用于诊断和验收工具。新批次评分合同、时序快照和决策件是逐步获得可比较材料的必需输入。
- 程序改版后重新冻结新 cycle；旧批次继续调用原对照目录的 `ENGINE.py`。没有覆盖旧记录的写入选项。
- 读取批次时，程序从绑定的 cycle 报告和边界重算 `BATCH.json`，从决策当时的可见结果和上下文重算每个 `D*.json`，从绑定的结果文件重算每个 `O*.json`（时间戳除外）。任何字段对不上即拒绝，并列出不一致的字段；连带改写哈希引用也一样。要改预算、策略或评价，只能冻结新边界、开新批次。整段删除记录或连同边界整套重写不在此检查范围内，需靠研究线自己的版本记录发现。重算只用记录自身的输入（cycle 报告、边界、上下文、结果文件）；它们所附的证据清单（上下文和边界引用的文档、协议、目标文件、候选依据）在写入时核对，之后编辑这些文档不会让在途批次停下，新的决策和结果仍在写入时核对各自引用的证据。
- 单批写入使用独占短锁。同一锁存在时检查本批实际写入者，不自动删除别人的锁；无依赖的其他工作继续。
- `pending_result`、`reflection_due`、`batch_closed` 是调度批次状态，不是整条研究线的暂停指令。


## 7. 多方向具体候选试点（2026-09-23）

项目入口新增可选 frontier_pilot，完整输入及预算见[分支研究试点](分支研究试点.md)。它在新批次边界启用，实际 next 返回 candidate_id / hypothesis_id / family / spec 与比较记录；不再让执行器在选完抽象动作后临时只生成一个假设。check-frontier 验收准备池，不派发实验。旧批次继续用其已绑定的 ENGINE.py，项目入口与旧批次版本不同应回到冻结程序，不重建在途身份。

## 8. RRSI 约束的流程改进（MS015，2026-09-27）

按 [MS015](../analysis/research_method_supervision_20260922/MS015_RRSI流程改进.md)在下一自然 `cycle` 边界启用以下选项。第一轮省略 `--rrsi-history`；同一方法链后续传上一份报告。历史比较不改变在线批次，相同输入和实现时直接引用有效回执。

```powershell
python -X utf8 -B engine/research_scheduler.py cycle --rrsi --branch <structure或ml> --world <本线有效WORLD.json> --incumbent <本线当前POLICY.json> --rrsi-history <本线上一份RRSI的REPORT.json> --out <本线新比较目录>
```

`CONTRACT.json.rrsi` 事前固定开发输入、父本、历史链、每候选改动上限和成本口径。2026-10-15 P1 的新引擎从首轮起每候选只改一个组件，最多两个候选，实际预算和反思频率不变；旧冻结引擎仍按原改动上限执行。可改组件为优先级与延伸深度；相同输入下已提出的候选不重复生成，未知与失败都保留。三个可比、完整且无改善的轮次触发已有名额内的未试组件探索；每第三个真实改进轮次优先比较尚未尝试的浅层延伸候选，反馈也可能让它更早出现，空间已尽保留原版。

### 10.1 候选与历史统计

普通 cycle 和 RRSI cycle 都先把全部候选与同一冻结父本比较，再从准入集合选择。唯一 Pareto 最优可选；多个候选在全部评价维度完全等价时，按政策内容的规范 JSON 顺序作确定性选择；互有取舍则保留父本，记录 `selection.reason=incomparable_tradeoff`。保留集不参与候选生成或消解取舍，也不在首选失败后改挑另一候选试保留集。

P0 报告使用 `rrsi.schema=research_rrsi.v2`，P1 的 v3 保留下列统计语义。同一开发输入的历史字段分为 `attempted_fields`（包括未知尝试）、`evaluated_fields`（比较完整）、`admitted_fields`（通过本轮父本及历史底线门槛）。兼容字段 `tried_fields` 等于 `evaluated_fields`；未知尝试仍保留并用于同输入排重，不代表已验证组件，也不无限重试。

`development_summary.observed_best_quality` 保留看到的分数，`admissible_best_quality` 只纳入完整合格的父本和通过门槛的候选；`best_quality` 是后者的兼容别名。下一轮底线只读取合格分数，不读取因成本、请求、覆盖等被拒的高分。信息／工程阶段这三个经济分数字段均可为空。

旧 v1 历史可以继续校验引用链并排重，但其统计不自动升级为 v2 的有效评价、停滞或合格底线，数量记在 `legacy_statistics_excluded`。不改写旧 REPORT。改变评价或成本合同应开启新比较链，不把旧口径统计搬入。

### 10.2 显式分阶段评价

未提供 `evaluation_contract` 时仍为经济阶段，沿用原账户评分器；不会根据 `quality=null` 猜测阶段。信息／工程阶段在 WORLD 和下一批边界增加同一 `evaluation_contract` 引用，合同格式如下（所有引用都需用真实绝对路径和 SHA256）：

```json
{
  "schema": "research_stage_evaluation.v1",
  "stage": "information",
  "protocol": {"path": "事前PLAN或SPEC的绝对路径", "sha256": "真实哈希"},
  "questions": ["事前冻结的问题编号"],
  "criteria": [{"id": "source_identity", "path": "source_identity_ok", "op": "eq", "expected": true}]
}
```

`stage` 可为 `information` 或 `engineering`；`criteria` 支持布尔／有限数值 `eq` 和数值 `ge / le`，不接受任意可执行表达式。它表达事前要验证的事实或工程判据，不制造另一套加权总分。WORLD 的 `metric_contract` 由 `metric_identity(branch, quality_ref, evaluation_ref)` 生成，仍绑定原经济质量合同身份；开发、保留和试点不能混阶段或偷换合同。

此阶段 `CONTEXT.json.question` 必须是合同内问题，`next` 将其冻结到决策件；`observe` 拒绝改换问题。`verified_information` 的结果必须 `quality=null, resolved=true, substantive=true`，并提供 `stage_evidence`：

```json
{
  "finding": {"path": "原发现JSON绝对路径", "sha256": "真实哈希"},
  "verification": {"path": "独立复核JSON绝对路径", "sha256": "真实哈希"}
}
```

发现 JSON 包含 `question` 和判据读取的实际字段，例如 `source_identity_ok`。独立复核 JSON 包含 `schema=research_stage_verification.v1`、`question`、`evaluation_contract` 引用、相同 `finding` 引用、`independent=true`、实际 `verifier` 身份和 `checks`（每个判据 ID 对应布尔结论）。程序重新计算实际字段，并要求每项与复核一致；仅写 `resolved=true` 或“已核验”不能替代上述原件。核验人的实际独立性仍由原研究核验流程负责，程序验证绑定和判据一致性。

“已可靠回答”和“达到事前判据”分别统计。明确的负结果可以增加已回答问题数，但不能伪装成达标。RRSI 比较要求 `stage_passed_questions` 和结论覆盖不退化且至少一问达标，仍受请求、错误、成本和保留集门槛约束。信息／工程小试使用 `min_stage_passed_questions`、`min_resolved_questions`、`max_requests`，不填写经济 `min_quality`；`review-pilot` 返回本阶段判据结果，经济分数保持空，`economic_promotion=false`。经济阶段继续要求 `min_quality` 和原账户独立核验。

### 10.3 五项成本贯穿记录、回放和试点

新口径选择性增加 `cost_contract` 引用到 WORLD 和下一批边界，合同为：

```json
{
  "schema": "research_cost_contract.v1",
  "unit": "resource_seconds",
  "phases": ["generation", "execution", "verification", "maintenance", "communication"],
  "accounting": "nonoverlapping_active_resource_time"
}
```

这是工作资源耗时之和，不能叫墙钟提速。计时采集者须将同一资源的活动区间分开：不能把包含核验的执行总时长再加核验时长，不能重复加入包含这些活动的等待／墙钟总时长；原 `total_seconds` 仅并列保留，不再加到新五项合计。

每个结果可增加 `cost_receipt` 引用，引用的 JSON 为：

```json
{
  "schema": "research_cost_receipt.v1",
  "cost_contract": {"path": "冻结成本合同绝对路径", "sha256": "真实哈希"},
  "kind": "decision",
  "subject": {"path": "本次D0001.json绝对路径", "sha256": "真实哈希"},
  "phases": {
    "generation": null,
    "execution": [{"id": "原计时事件的稳定唯一ID", "evidence": {"path": "原计时JSON绝对路径", "sha256": "真实哈希"}, "seconds_path": "execution_seconds"}],
    "verification": null,
    "maintenance": null,
    "communication": null
  }
}
```

五项必须显式列出：`null` 表示未测全，`[]` 表示确认无这项活动，数组表示实际事件。程序从 `evidence` 的 `seconds_path` 读取有限非负时长，不接受手工另填一个覆盖总数。原计时件需保留事件身份，避免不同计时恰好同内容而无法区分。共享准备成本跨节点复用同一事件 ID 和原引用；同事件只加一次，ID 相同但证据或阶段冲突、同一测量换 ID 重复计费均拒绝。真实重试应有自己的新计时事件，会增加成本。

链条已接到 `observe → O记录 → ledger → export WORLD → replay / cycle → review-pilot`。`cost_accounting` 保留事件、各阶段已知小计及缺项；`metrics.all_in_method_cost_seconds` 只在被观察节点的五项完整、无不支持路径时给出总数。此范围不自动包含整个研究项目开销。报告按 WORLD 列在 `rrsi.method_cost_by_world`，不把开发、保留和多政策重复回放计时相加成新支出；旧无明确整体范围的 `rrsi.all_in_method_cost_seconds` 保持空。

选择新成本合同时，RRSI 用该合计准入，不能降回旧 `total_seconds` 躲过缺项；试点事前填写 `pilot_criteria.max_all_in_method_cost_seconds`，缺项或超限回退。未选择新合同的历史链继续使用原节点总成本和 `max_total_seconds`，不宣称补齐了全流程成本。成本合同变化不允许在候选部署时临时切换。

### 11.2 失败证据、预测核对与下一轮提案

新 RRSI 报告使用 `research_rrsi.v3`。每个 CANDIDATE 在回放前冻结一个组件和行为预测，报告的 `rrsi.feedback` 引用原 INCUMBENT、CANDIDATE、REPLAY 文件，并记录：

- 不支持的延伸路径 → 对应开发 WORLD 内容哈希与 trace 步骤 → 尝试收浅深度，预测不支持动作减少。
- 已观察到实现故障但修复不优先 → 对应节点 → 尝试先修复，核对修复动作是否增加。
- 同问题多次未解决且延伸优先 → 对应问题 → 尝试先探索，核对重复未解决次数是否减少。
- 没有这些可执行诊断时，仍保留原有限候选空间；行动顺序候选核对实际轨迹是否改变，浅层候选核对决策调用是否减少。预测命中本身不等于准入或提效。

`prediction_check` 保留预期与实际行为、`hit / miss / unknown`、质量／阶段覆盖／请求／故障及事前回归样例的意外退化、相同成本口径的前后值和差额。完整成本缺失时差额为空，不能退回旧节点秒数当节省。仅完全可比的开发测量进入 `feedback_guidance`：预测落空或退化降低该组件的后续提案优先级；通过原准入且命中的组件保留正反馈；未知中性。同父本、同开发输入、同阶段和成本口径才复用，heldout 结果不进入生成或反馈统计。历史反馈会改变下一项具体提案，但不能扩大两项上限、改预算、反思频率或评分器。

需要保护具体成功样例时，在供比较的**新冻结 WORLD**中事前列出 `method_regression_questions`。程序要求父本确实观察到并可靠回答这些问题，候选仍可靠回答，既有该问题的经济质量或阶段达标不能下降；未知样例不按通过处理。该字段属于当前回放比较的回归约束，不自动替代各线真实试点的原验收合同；不要事后修改旧导出 WORLD。未声明具体样例的旧输入仍保留原整体质量、覆盖、成本等门槛。

v1 历史继续只用于身份链和排重；v2 可复用 P0 已明确的有效统计，但不会补造预测结果。v3 使用反馈前核对原基线、候选及回放的哈希。旧报告与组合改动仍保留原解释，不分别归功于多个组件。

`cycle --rrsi` 的可执行修改面仍只有 `priority / max_depth`；其 `feedback.unsupported_components` 只描述该动作回放入口。2026-10-15 新增的 harness 入口另行支持提示词、候选生成和上下文组织，须用实际 Agent 输入／输出与配对评价，不能拿动作回放代替。检索源扩展、任意代码重写和核验回执自动复用未接入。新选择器和新 harness 的研究收益仍需要下一合法边界上的真实输入、各线成本采集及未参与设计的匹配问题前瞻比较。

## 12. 反思到 harness 改进（2026-10-15）

入口、完整格式和操作顺序见 [Harness 反思与改进闭环](Harness反思与改进.md)。新增 `harness-init --spec --out` 冻结模型、预算、原始上下文、基线、案例、判据、ENGINE 与 HARNESS；`harness --round --request` 承接 `propose / prepare / generation / result / review`。当前 Agent 实际读取返回的任务，按所选版本反思并生成原格式候选池；程序只组装、核验和比较，不另外调用模型或执行研究。

每轮最多两个同父本候选、每项一个组件，全部候选先冻结，再在相同原始输入与预算下评价；保留失败、未知和独立复核。原成功判据逐案例保留，成本缺失不补零；单次五项成本与轮次公共开销分别入账。开发优势只产生有界试点资格，夹具不能部署。

新边界通过 `harness_deployment` 绑定已评审版本、实际任务和生成池，原 `frontier_pilot.initial_frontier` 必须指向该池；保持原 policy、selector、成本合同和执行流程，不与另一项调度试验叠加。D/O 自动记录版本来源，批内不可换池。`review-pilot` 结束保留回退指向，下一轮 `execution_feedback` 将实际决策／结果送回 REFLECTION_TASK；未接入的旧批次仍按原合同运行。

这完成工程上的闭环，不自动证明 Agent 在真实研究中已使用新版、生成质量更好或费后收益改善；真实输入、完整成本、前瞻比较与经济确认按各自证据报告。新写入器的文件／字节计数与复用范围保留在 CONTRACT／REVIEW，不另建研究状态或定时任务。

## 13. v2 新增接口（2026-10-16）

本节只对新冻结的 ENGINE 生效。新工具全部只用标准库，不调用模型、不提交实验。回放 v2 用 `cycle ... --replay-semantics v2` 开启。

### 13.1 边界新增字段

```json
{
  "branching": {"siblings": 2},
  "walkforward_contract": {"path": "冻结的滚动验证合同绝对路径", "sha256": "真实哈希"}
}
```

`walkforward_contract` 由 `python -X utf8 -B engine/research_walkforward.py default-contract` 生成默认版后按本线修改并冻结；边界须同时以 `walkforward_runtime: {path, sha256}` 绑定打分器文件（通常是 `engine/research_walkforward.py`），`start-batch` 把它复制为批次内的 `WALKFORWARD.py`，之后每次读取批次都核对副本哈希。冻结后，每个经济结果的 `observe` 输入须带 `"walkforward": {path, sha256}`，该裁决须写明候选与父本逐日权益文件，两份文件也须列在本结果的 `evidence` 中；`observe` 用冻结打分器从这两份文件重算，结论或胜出折数不一致即拒绝。`valid_improvement` 须同时满足账户评分改善和 `decision=pass`。候选与父本的交易日历必须完全一致，各窗口行数不得低于工作日数的 85%（`min_calendar_coverage`），否则拒绝计算或记 `insufficient_data`。

### 13.2 计时与成本回执

```powershell
python -X utf8 -B engine/research_timing.py run --event-id B130-account --phase execution --out <本批>/timers/B130-account.json -- python <执行器> <参数>
```

未计时的阶段保持 `null`（未知）；只有确认完全没有该阶段活动时才用 `--none`。同一资源上时间重叠的计时拒绝组装，防止重复计费。
